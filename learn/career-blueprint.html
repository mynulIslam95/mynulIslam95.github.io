0.1 তোমার Starting Point

Full-time Software Job না থাকলেও coursework, personal projects, collaboration আর relevant working-student work থেকে evidence তৈরি করা যায়। CV তে সত্যিকারের Automation, Troubleshooting আর Stakeholder Work দেখাবে। IT Operations কে Software Development বলে লিখবে না।

Targets: New-grad FDE • Graduate SWE • SDE I • Associate SWE • Early-career SWE • Junior Applied AI Engineer

0.2 Hiring Reality

Degree Completion Date, Graduation Window, Work Authorization আর Team Language আগে Check করবে। US Role এর জন্য US Work Authorization আর Germany Role এর জন্য Germany Work Rights আলাদাভাবে Confirm করতে হবে।

Certificates Supporting Evidence। Coding, Debugging আর Independent Implementation হবে Main Evidence।

0.3 Skills যা হাতে দেখাতে হবে

Python/OOP, SQL/Transactions, Git/PRs, DSA, OS/Networking, HTTP/APIs, Tests, Security, Docker/AWS, Logs আর Debugging। AI Track এ RAG, Evaluation, Structured Outputs আর Safe Tool Use।

প্রতিটা Project এ একটা Bug Reproduce → Root Cause → Fix → Regression Test এর Story রাখবে।

0.4 Project 1: Customer Operations Platform

Customers, Orders আর Tickets Manage করার Fullstack App। FastAPI, PostgreSQL, React/TypeScript, Docker আর AWS ব্যবহার করবে।

Build checklist: Login/RBAC • Tenant Isolation • CRUD/Search/Pagination • Transaction-safe Updates • Webhook • Background Jobs/Retry • Duplicate-event Protection • Tests/CI • Health Checks/Rollback • Load Test।

0.5 Project 2: Enterprise Knowledge & Action Assistant

Company Documents থেকে Permission অনুযায়ী Cited Answers দেবে। Tool দিয়ে Ticket Draft করবে, Human Approval এর পরে Sandbox Ticket Create করবে।

Build checklist: Ingestion • RAG • No-answer Behaviour • Citations • Validated Tool Arguments • Approval/Audit Trail • Evaluation Dataset • Prompt-injection Tests • Cost/Latency। Junior AI Roles এর জন্য ছোট Ticket Classification Baseline যোগ করবে: Train/Test Split, Leakage Checks, Precision/Recall/F1 আর Error Analysis।

0.6 Portfolio Evidence Pack

দুইটা Repository, Working Demo, ছোট Video, Architecture Diagram, Setup Instructions, Automated Tests, CI আর Meaningful PRs রাখবে। Real User Feedback পেলে Document করবে।

Performance বা Evaluation Numbers বানাবে না। কী Dataset, Load আর Environment এ Measure করেছ লিখবে। একই Projects, Software Role এ প্রথমটা আগে, AI Role এ দ্বিতীয়টা আগে দেখাবে।

0.7 Certificates: Skills আগে, Exam পরে

দুইটা choice থাকছে: AWS Certified Developer - Associate আর Databricks Certified Generative AI Engineer Associate। প্রথমটা cloud development evidence-এর সঙ্গে, দ্বিতীয়টা Databricks-based AI implementation-এর সঙ্গে মানায়। কোনোটাই এই ছয়টা role-এর universal requirement না।

AWS exam-এর official page hands-on experience recommend করে। Databricks-এরও practical platform experience দরকার। Bootcamp শেষ করলেই exam-ready ধরে নেবে না। AWS guide এখন version transition দেখাচ্ছে, তাই booking-এর exam code অনুযায়ী live guide follow করবে। Exam version, fees আর required services official page থেকে আবার check করবে।

0.8 Interview Preparation

DSA Pattern Practice Python Data Structures শেখার পর থেকেই চলবে। 75টা Core + 25টা Optional Problem দিয়ে শুরু, Weak Patterns অনুযায়ী Expand করবে। SQL, Debugging, Junior System Design আর Project Deep Dive Practice করবে।

Behavioral Stories: Ownership, Failure, Conflict, Feedback, Ambiguity, Customer Communication। STAR Notes নিজের সত্যিকারের experience, team work আর project decisions থেকে লিখবে।

0.9 Job Security নিয়ে বাস্তব কথা

কোনো Company Layoff-proof না। Hiring আর Layoffs একই Company তে হতে পারে। Revenue-generating Product, Approved Headcount, বাস্তব Customer Usage আর ভালো Junior Mentorship খুঁজবে।

Manager Questions: Role নতুন নাকি Replacement? Budget Approved? গত বছরে Team কীভাবে বদলেছে? Mentor কে? প্রথম 6 মাসের Success Criteria কী? Startup হলে Runway সম্পর্কে কী Share করতে পারবেন?

0.10 তোমার Execution Order

Foundation → ছোট Projects → Deployed Backend/Fullstack App → AI Assistant → Interview Mocks। AI Assistant দিয়ে কাজ করলেও Code বুঝতে, Test করতে আর Debug করতে হবে।

8টা Practice Milestone + 2টা Capstone Roadmap এ আছে। কিছু কাজ Reuse হবে। CV তে প্রধান দুইটা Capstone দেখাবে। নতুন Career Blueprint Orientation Module, অতিরিক্ত Project না।

LeetCode: Count নয়, independent skill

75 Core + 25 Optional unique problems রাখা হয়েছে। এটা নিজের curated list, official LeetCode 75 বা guaranteed company question bank না। Patterns-এর সঙ্গে lesson mapping Module 5-এ থাকবে। Bit operations, sorting implementation ও SQL drills আলাদা lab হিসেবে থাকবে, problem count inflate করা হয়নি।

প্রতিটি solution-এ constraints, invariant, complexity আর edge cases explain করো। Assisted/independent label রাখো; 2, 7 ও 30 দিন পরে revision করো। Weekly unseen mock-এর পরে ভুলের pattern দেখে next practice ঠিক করো। Company recruiter অন্য format দিলে সেটাই follow করবে।

নিজের evidence দিয়ে module close করো

Topic explain করতে পারছ → small implementation করতে পারছ → failure reproduce করতে পারছ → test বা measured result দেখাতে পারছ। Module labs-এর acceptance criteria পূরণ হলে এগোবে। শুধু video দেখা বা title tick করা completion না। Coding explanations Banglish হতে পারে, কিন্তু README, PR summary, demo আর interview rehearsal English-এও practice করবে।

Goal: software foundations দিয়ে শুরু করে দুইটা useful deployed project ও interview evidence তৈরি করা। 80/20 এখানে priority rule; exact measured learning-efficiency ratio না।

এটা estimated plan, completion promise না। প্রতি চার সপ্তাহে actual hours আর independent performance review করবে। Delay হলে extra features ও optional depth cut করবে; testing, security ও honest evaluation বাদ দেবে না।

Execution sequence

  1. Weeks 1–8: Modules 1–4 foundation; Lesson 1.2-এর পরে DSA parallel। Small CLI ও SQL milestone reuse করো।
  2. Weeks 9–16: Modules 6–10 essentials ও Capstone 1-এর minimum release। Module 16-এর relevant API/data/failure design আর Module 17-এর customer brief project build-এর সময় পড়ো।
  3. Weeks 17–24: Modules 11–15 essentials ও Capstone 2-এর minimum release। Retrieval baseline, permissions, evaluation ও one approved action আগে।
  4. Weeks 25–32: hardening, independent mocks, external review, targeted applications ও buffer। Modules 16–18-এর remaining relevant practice integrate করো।

Weekly starting split: 10h build/debug, 4h DSA/SQL, 3h targeted reading, 2h English/application/collaboration, 1h review। Mock interview reading বা DSA block replace করতে পারে; extra workload হিসেবে যোগ করবে না।

Role-specific priority

Graduate SWE / SDE I / Associate / Early Career: Modules 1–10, 16, 18 ও Capstone 1 primary। Capstone 2-এর basic version secondary। Junior Applied AI: একই foundation-এর সঙ্গে 11–15 ও Capstone 2 primary; PyTorch depth relevant vacancy চাইলে। New-grad FDE: দুই project-এর সঙ্গে discovery, integration, English demo, UAT ও handoff primary।

এখন defer: 25 Optional LeetCode problems, Kubernetes, LoRA, complex multi-agent systems, elaborate UI, second cloud/vector store আর certificate-specific extra service labs। Java/Kotlin vacancy target করলে ছোট bridge দরকার হতে পারে; সব language একসাথে শেখা লাগবে না।

Minimum capstones, then harden

Capstone 1 minimum: one customer/order/ticket journey, two tenants, ownership checks, safe transactions, minimal UI, one integration, tests, CI ও one deployment। Capstone 2 minimum: one document collection, permission filters, keyword baseline, cited/no-answer responses, frozen evaluation queries ও one human-approved sandbox action। আগের acceptance checklist hardening backlog; MVP থেকে public portfolio release-এর আগে critical security/recovery tests করতে হবে।

Mastery gates

  1. Foundation gate: নতুন transaction input independently process, invalid data handle, query explain ও একটি seeded bug fix করতে পারবে।
  2. Software gate: অন্য মানুষ README থেকে Capstone 1 run করতে পারবে; tests দিয়ে tenant boundary, failed write আর retry behavior দেখাতে পারবে।
  3. AI gate: held-out results দিয়ে baseline compare, bad answer-এর origin trace আর denied action/permission case explain করতে পারবে।
  4. Interview gate: unfamiliar coding problem solve করতে করতে reasoning explain, tests/complexity discuss, seeded issue diagnose আর project trade-off defend করতে পারবে। Mock feedback দিয়ে weakness track করো; question count-কে pass guarantee ধরবে না।

Actual collaboration evidence

একজন peer/mentor দিয়ে real PR review করাও, feedback অনুযায়ী change করো আর একজনকে README follow করে setup করতে দাও। Reviewer না পেলে open-source-এ ছোট relevant contribution চেষ্টা করো। Self-review-কে external review বলবে না।
