START FROM ZERO

Complete setup walkthrough

These instructions describe the visible menus and terminal actions. The exact screen can vary between Windows, macOS and Linux.

1. Install and verify Python

Open https://www.python.org/downloads/ and install a supported Python 3 release. On Windows, use the installer option that adds Python to PATH if offered. Open a NEW terminal after installation.

python --version

Check the result: A version such as Python 3.x. If unavailable on macOS/Linux try python3 --version. On Windows try py --version. Do not type the word Python as a terminal command.

2. Install VS Code and the Python extension

Install VS Code from https://code.visualstudio.com/. Open it, select the Extensions icon on the left, search Python, choose the extension published by Microsoft and install it.

File → Open Folder → select python-foundations

Check the result: The Explorer on the left shows the folder. Create a file named hello.py using the New File icon. The .py suffix is essential.

3. Open the terminal in the correct folder

In VS Code select Terminal → New Terminal. Check the folder path before running scripts. The terminal is not the same as the editor.

pwd  # macOS/Linux
cd   # Windows Command Prompt

Check the result: The printed path should end in python-foundations. If not, use cd with the path to the folder or reopen it in VS Code.

4. Run, save and troubleshoot

Type print('It works!') in hello.py. Save using Ctrl+S or Cmd+S. Run the file from the terminal.

python hello.py

Check the result: Expected output: It works! If python is unavailable try python3 hello.py (macOS/Linux) or py hello.py (Windows). If the script is missing, verify the folder and exact filename.

5. Understand the file layout

A project should keep source files, test files and input data together. Generated files should be distinguishable from source files.

python-foundations/
  hello.py
  orders.csv
  main.py
  test_main.py
  README.md
  .gitignore

Check the result: A filename ending in .csv is a data file, not Python code. A file named README.md documents commands. .gitignore excludes temporary folders such as .venv/.

6. Run code with confidence

Make one change at a time, save, predict the output, run and compare. When an error occurs, read the final traceback line, inspect the line number and print intermediate values.

print('Step 1')
print(2 + 3)

Check the result: Expected output is Step 1 on the first line and 5 on the second. Practice removing a closing parenthesis, observe SyntaxError and restore it.

LESSON 2

Variables, types and arithmetic

Understand

A variable is a name attached to a value. Text is str, whole numbers are int, decimals are float and true/false values are bool. Python evaluates the right side of = and stores the result under the name on the left.

Follow along

Calculate the total for an order. Change quantity and confirm the result changes. Use type(price) to inspect the value.

product = 'Notebook'
price = 12.50
quantity = 3
total = price * quantity
print(product, total)
print(type(price))

Expected result

Notebook 37.5
<class 'float'>

Why this skill matters at work

Most data tasks start by assigning values to names and calculating a result. Data types matter because Python will not automatically treat text such as '12.50' as money.

Understand the example, line by line

  1. product is a str because its value is enclosed in quotes. It describes an item, not a number.
  2. price is a float because 12.50 contains a decimal point. quantity is an int because 3 is a whole number.
  3. total = price * quantity multiplies the two numeric values and stores the result.
  4. print(product, total) displays both values separated by a space. type(price) reports the Python type of price.

Second worked example

print(price_number * 2)
print(type(price_text).__name__)

Understand

A list stores an ordered collection, such as multiple orders. A dictionary maps a key to a value, such as a product name to its price. Use a list when order or repeated items matter. Use a dictionary when values need names.

2

Why this skill matters at work

Real data consists of multiple records with named fields. Lists and dictionaries are the most frequently used Python structures for handling those records.

Understand the example, line by line

  4. orders[0]['category'] accesses the category field of the first dictionary. len(orders) counts list elements.

LESSON 4

Conditions and loops

Understand

A condition chooses what happens based on True or False. A for loop repeats an operation for each item. Indentation groups statements, so spaces are part of Python syntax.

Follow along

Reject orders with nonpositive prices. Add a third valid order and confirm the total increases.

orders = [{'price': 10, 'quantity': 2}, {'price': -3, 'quantity': 1}]
revenue = 0
for order in orders:
    if order['price'] <= 0:
        continue
    revenue += order['price'] * order['quantity']
print(revenue)

Expected result

20

Why this skill matters at work

A data pipeline usually processes many records. Loops avoid copying the same code for each row, while conditions decide whether each row should be accepted.

Understand the example, line by line

  1. revenue starts at zero before processing any records.
  2. for order in orders takes one dictionary from the list at a time.
  3. if order['price'] <= 0 checks whether the price violates the rule. continue skips the remaining statements for that row.
  4. revenue += ... is shorthand for revenue = revenue + .... Its indentation makes it part of the loop but outside the if block.
  5. print(revenue) runs after the loop and shows the accumulated result.

Second worked example

numbers = [3, -1, 5, 0]
valid = []
for number in numbers:
    if number <= 0:
        continue
    valid.append(number)
print(valid)
print(sum(valid))

Expected output

[3, 5]
8

Try a different problem

Show one possible solution after attempting

revenue = 0
rejected = 0
for order in orders:

        rejected += 1

  1. What happens when continue runs?

LESSON 5

Functions and return values

Understand

A function gives a name to reusable logic. Parameters receive inputs and return sends a result back. A function should ideally do one clear job. print displays a value but does not return it.

Follow along

Write a function that calculates an order's total and reuse it for two orders.

def order_total(price, quantity):
    if price < 0 or quantity < 0:
        raise ValueError('Negative values are not allowed')
    return price * quantity

print(order_total(12, 3))

Expected result

36

Why this skill matters at work

Functions make programs easier to test, reuse and maintain. Separating reading, validation, calculation and writing is a core habit in data engineering.

Understand the example, line by line

  1. def introduces a function named order_total.
  2. price and quantity are parameters: values supplied when the function is called.
  3. The if statement validates the inputs. raise ValueError stops normal execution if the rule is broken.
  4. return gives the calculated result back to the caller. print is used outside the function to display that result.

Second worked example

def calculate_tax(subtotal, rate=0.19):
    return subtotal * rate

amount = calculate_tax(100)
print(amount)
print(calculate_tax(100, 0.07))

Expected output

19.0
7.000000000000001

LESSON 6

Errors and debugging

Understand

An error message contains an exception type and a traceback showing where execution failed. Read the final line first, then locate the referenced line. Catch only errors you can meaningfully handle; do not hide every failure with a broad except.

Follow along

Turn user-provided price text into a number. Test valid and invalid inputs.

def parse_price(raw):
    try:
        price = float(raw)
    except ValueError:
        return None
    if price < 0:
        return None
    return price

print(parse_price('9.50'))
print(parse_price('unknown'))

Expected result

9.5
None

Why this skill matters at work

Business datasets frequently contain unexpected values. Debugging is the process of finding the cause, not just hiding the error.

Understand the example, line by line

  1. try contains the operation expected to fail for some user input.
  2. float(raw) converts numeric text to a number. Text such as 'unknown' raises ValueError.
  3. except ValueError catches that specific expected problem and returns None.
  4. The negative-price check applies a business rule even when conversion succeeds.
  5. Unexpected exceptions should generally remain visible until their cause is understood.

Second worked example

values = ['12.5', 'bad', '0']
for value in values:
    try:
        number = float(value)
    except ValueError:
        print('Rejected:', value)
    else:
        print('Accepted:', number)

Expected output

Accepted: 12.5
Rejected: bad
Accepted: 0.0

Try a different problem

Write parse_quantity(raw) that accepts only positive whole-number strings. It should return None for '2.5', '-1', 'abc' and '0'. Explain each rejected case.

Show one possible solution after attempting
def parse_quantity(raw):
    try:
        number = int(raw)
    except (ValueError, TypeError):
        return None
    return number if number > 0 else None

for value in ['3', '2.5', '-1', 'abc', '0']:
    print(parse_quantity(value))

Explain without looking at the code

  1. Why should except Exception usually be avoided here?
  2. What is the first useful part of a traceback to read?
  3. What is the difference between a conversion error and a business-rule failure?
Practice, debug and explain: complete walkthrough

LESSON 7

Files, paths, CSV and JSON

Understand

A file persists data after the program exits. pathlib creates portable paths. CSV stores rows and columns as text. JSON stores nested objects and arrays. The csv module reads structured CSV more safely than splitting on commas.

Follow along

Create orders.csv in the project folder. Run the reader and inspect each row. Notice that CSV values are strings until converted.

from pathlib import Path
import csv

file_path = Path('orders.csv')
with file_path.open(newline='', encoding='utf-8') as file:
    reader = csv.DictReader(file)
    for row in reader:
        print(row['category'], row['price'])

Expected result

Books 10.00
Office 5.00

Why this skill matters at work

CSV is one of the most common formats exchanged by analytics teams. File paths, column names and data conversion are frequent sources of production failures.

Understand the example, line by line

  1. Path('orders.csv') represents a file location relative to the terminal's current working directory.
  2. with ... open(...) opens the file and closes it even if processing fails.
  3. csv.DictReader reads the header row and returns each subsequent row as a dictionary.
  4. row['category'] looks up a named column. All CSV cell values are initially strings.
  5. The code prints the category and price from each row without converting the price yet.

Second worked example

import csv
from pathlib import Path
with Path('orders.csv').open(newline='', encoding='utf-8') as f:
    for row in csv.DictReader(f):
        price = float(row['price'])
        quantity = int(row['quantity'])
        print(row['category'], price * quantity)

Expected output

Books 20.0
Office 15.0

def parse_order(row):
    try:
        category = (row['category'] or '').strip()
        price = Decimal(row['price'])
        quantity = int(row['quantity'])

from collections import defaultdict
from decimal import Decimal, InvalidOperation
from pathlib import Path
import csv

REQUIRED = {'category', 'price', 'quantity'}

def process_orders(input_path):
    totals = defaultdict(lambda: Decimal('0.00'))
    rejected = []
    with Path(input_path).open(newline='', encoding='utf-8') as handle:
        reader = csv.DictReader(handle)
        if not reader.fieldnames or not REQUIRED.issubset(reader.fieldnames):
            raise ValueError('CSV must include category, price and quantity')
        for line_number, row in enumerate(reader, start=2):
            try:
                category = (row['category'] or '').strip()
                price = Decimal(row['price'])
                quantity = int(row['quantity'])
                if not category or not price.is_finite() or price < 0 or quantity <= 0:
                    raise ValueError('Invalid category, price or quantity')
                totals[category] += price * quantity
            except (ValueError, InvalidOperation, TypeError, KeyError) as error:
                rejected.append({'line': line_number, 'reason': str(error)})
    return totals, rejected

def write_csv(path, columns, rows):
    with Path(path).open('w', newline='', encoding='utf-8') as handle:
        writer = csv.DictWriter(handle, fieldnames=columns)
        writer.writeheader()
        writer.writerows(rows)

def main():
    totals, rejected = process_orders('orders.csv')
    write_csv('summary.csv', ['category', 'revenue'], [
        {'category': category, 'revenue': f'{amount:.2f}'}
        for category, amount in sorted(totals.items())
    ])
    write_csv('rejected.csv', ['line', 'reason'], rejected)
    print(f'{len(totals)} categories; {len(rejected)} rejected rows')

if __name__ == '__main__':
    main()

from collections import defaultdict
from decimal import Decimal, InvalidOperation
from pathlib import Path
import csv

REQUIRED = {'department', 'unit_cost', 'units'}

def process_expenses(path):
    totals = defaultdict(lambda: Decimal('0.00'))
    rejected = []
    with Path(path).open(newline='', encoding='utf-8') as f:
        reader = csv.DictReader(f)
        if not reader.fieldnames or not REQUIRED.issubset(reader.fieldnames):
            raise ValueError('Required columns: department, unit_cost, units')
        for line, row in enumerate(reader, start=2):
            try:
                department = (row['department'] or '').strip()
                cost = Decimal(row['unit_cost'])
                units = int(row['units'])
                if not department or not cost.is_finite() or cost < 0 or units <= 0:
                    raise ValueError('Invalid department, cost or units')
                totals[department] += cost * units
            except (ValueError, InvalidOperation, TypeError, KeyError) as error:
                rejected.append({'line': line, 'reason': str(error)})
    return totals, rejected

def write_csv(path, columns, rows):
    with Path(path).open('w', newline='', encoding='utf-8') as f:
        writer = csv.DictWriter(f, fieldnames=columns)
        writer.writeheader()
        writer.writerows(rows)

def main():
    totals, rejected = process_expenses('expenses.csv')
    write_csv('department_summary.csv', ['department', 'total'], [
        {'department': dept, 'total': f'{value:.2f}'}
        for dept, value in sorted(totals.items())
    ])
    write_csv('rejected.csv', ['line', 'reason'], rejected)
    print(f'{len(totals)} departments; {len(rejected)} rejected rows')

if __name__ == '__main__':
    main()

Interview questions with detailed answer guidance

Question 1: When should a list be used instead of a dictionary?

A list stores a sequence and is suitable when item order, repeated entries or iteration by position matters. A dictionary stores key-value associations and is suitable for retrieving or updating a value by a meaningful key. In this project, rejected rows are kept in a list because every failed row must be preserved. Department totals are kept in a dictionary because totals are looked up by department name.

Example: A list of individual orders can contain repeated categories; a dictionary of totals maps each category to one accumulated amount.

Question 2: What is the difference between print and return?

print displays information for a person. return sends a value from a function to the calling code so it can be tested, combined with other values or written to a file. A function that only prints normally returns None.

Example: process_expenses returns totals and rejected rows so automated tests can inspect both. main prints a short run summary for the user.

Question 3: What causes KeyError, ValueError and FileNotFoundError?

KeyError occurs when accessing a dictionary key that is absent, for example row['unit_cost'] if the key is missing. ValueError occurs when a value is unsuitable for an operation, such as int('abc'). FileNotFoundError occurs when a file path cannot be opened because the file does not exist at that location. Debug by reading the last traceback line, inspecting the failing input and checking the current folder.

Example: Use row.keys() to inspect columns, print(repr(value)) for malformed text and Path.cwd() to inspect the working directory.

Question 4: Why should data validation happen before aggregation?

Invalid values can distort totals, cause crashes or silently produce misleading reports. Validation establishes whether a record is acceptable before it affects a metric. Rejected rows should be recorded with reasons so problems can be investigated rather than hidden.

Example: A negative cost or a malformed unit count must not be included in the department total. The rejected.csv file preserves evidence.

Question 5: How can a program be made safe to rerun?

Use predictable inputs and deterministic calculations. Overwrite output files deliberately rather than appending duplicates. Separate raw input from generated output and validate each run. For database pipelines, use idempotent writes or unique keys to avoid duplicate records.

Example: This project opens output CSVs in write mode, so a second run replaces the files. Confirm that the totals and row counts remain unchanged.
