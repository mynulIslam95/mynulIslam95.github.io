LESSON 2

Variables, types and arithmetic

Understand

A variable is a name attached to a value. Text is str, whole numbers are int, decimals are float and true/false values are bool. Python evaluates the right side of = and stores the result under the name on the left.

Follow along

Calculate the total for an order. Change quantity and confirm the result changes. Use type(price) to inspect the value.

product = 'Notebook'
price = 12.50
quantity = 3
total = price * quantity
print(product, total)
print(type(price))

Expected result

Notebook 37.5
<class 'float'>
Practice, debug and explain

Try price = '12.50'. Multiplication now behaves differently because text is not a numeric price. Convert validated input to a number with float(). For money in real financial systems, Decimal is often safer than float.

LESSON 3

Lists and dictionaries

Understand

A list stores an ordered collection, such as multiple orders. A dictionary maps a key to a value, such as a product name to its price. Use a list when order or repeated items matter. Use a dictionary when values need names.

Follow along

Add another order and look up the first order's category. Try accessing a missing key and observe the error.

orders = [
    {'category': 'Books', 'price': 10, 'quantity': 2},
    {'category': 'Office', 'price': 5, 'quantity': 3}
]
print(orders[0]['category'])
print(len(orders))

Expected result

Books
2
Practice, debug and explain

Change the first category. Use orders[0].get('discount', 0) to supply a safe default. A KeyError means a requested dictionary key does not exist.

LESSON 4

Conditions and loops

Understand

A condition chooses what happens based on True or False. A for loop repeats an operation for each item. Indentation groups statements, so spaces are part of Python syntax.

Follow along

Reject orders with nonpositive prices. Add a third valid order and confirm the total increases.

orders = [{'price': 10, 'quantity': 2}, {'price': -3, 'quantity': 1}]
revenue = 0
for order in orders:
    if order['price'] <= 0:
        continue
    revenue += order['price'] * order['quantity']
print(revenue)

Expected result

20
Practice, debug and explain

Replace <= with < and test a zero-price order. Explain why a business rule may treat free items differently. Be able to trace each loop iteration by hand.

LESSON 5

Functions and return values

Understand

A function gives a name to reusable logic. Parameters receive inputs and return sends a result back. A function should ideally do one clear job. print displays a value but does not return it.

Follow along

Write a function that calculates an order's total and reuse it for two orders.

def order_total(price, quantity):
    if price < 0 or quantity < 0:
        raise ValueError('Negative values are not allowed')
    return price * quantity

print(order_total(12, 3))

Expected result

36
Practice, debug and explain

Call order_total(-2, 3) and observe ValueError. Explain why returning a value is more useful for testing than only printing it.

LESSON 6

Errors and debugging

Understand

An error message contains an exception type and a traceback showing where execution failed. Read the final line first, then locate the referenced line. Catch only errors you can meaningfully handle; do not hide every failure with a broad except.

Follow along

Turn user-provided price text into a number. Test valid and invalid inputs.

def parse_price(raw):
    try:
        price = float(raw)
    except ValueError:
        return None
    if price < 0:
        return None
    return price

print(parse_price('9.50'))
print(parse_price('unknown'))

Expected result

9.5
None
Practice, debug and explain

Predict the results for '0', '-4', '' and '12x'. Put a breakpoint on the conversion line in VS Code and inspect raw. For business-critical money, learn Decimal after this lesson.

LESSON 7

Files, paths, CSV and JSON

Understand

A file persists data after the program exits. pathlib creates portable paths. CSV stores rows and columns as text. JSON stores nested objects and arrays. The csv module reads structured CSV more safely than splitting on commas.

Follow along

GUIDED MINI-PROJECT

Build a sales summary from a CSV

This is the same kind of small data-processing task used in entry-level analytics work. The program will read orders, reject invalid rows and write category totals. Complete each step before opening the full reference implementation.

  1. Create the project structure

    Make a new folder named sales-summary with orders.csv, main.py, test_main.py, README.md and .gitignore. Add .venv/ and __pycache__/ to .gitignore. Start with two rows and expand later.

  2. Prepare the input file

    Save this exact CSV as orders.csv: category,price,quantity Books,10.00,2 Office,5.00,3 Books,8.00,1 Office,wrong,2 Books,-4.00,1 The last two records are intentionally invalid.

  3. Implement validation

    Start with one row. Convert price and quantity inside try/except. Reject invalid numbers, negative prices and nonpositive quantities. Keep a reason for rejected rows.

  4. Calculate totals

    Use a dictionary keyed by category. For each valid row, add price × quantity to the category total. Prefer Decimal for currency.

  5. Export the report

    Use csv.DictWriter to write summary.csv with category and revenue columns. Write a separate rejected.csv so failures are visible.

  6. Verify and explain

    Expected totals: Books = 28.00 and Office = 15.00. Two rows must be rejected. Run with an empty file, a missing required column and malformed price. Add automated tests and explain the design without reading the code.

Show the complete reference implementation (main.py)
from collections import defaultdict
from decimal import Decimal, InvalidOperation
from pathlib import Path
import csv

REQUIRED = {'category', 'price', 'quantity'}

def process_orders(input_path):
    totals = defaultdict(lambda: Decimal('0.00'))
    rejected = []
    with Path(input_path).open(newline='', encoding='utf-8') as handle:
        reader = csv.DictReader(handle)
        if not reader.fieldnames or not REQUIRED.issubset(reader.fieldnames):
            raise ValueError('CSV must include category, price and quantity')
        for line_number, row in enumerate(reader, start=2):
            try:
                category = (row['category'] or '').strip()
                price = Decimal(row['price'])
                quantity = int(row['quantity'])
                if not category or not price.is_finite() or price < 0 or quantity <= 0:
                    raise ValueError('Invalid category, price or quantity')
                totals[category] += price * quantity
            except (ValueError, InvalidOperation, TypeError, KeyError) as error:
                rejected.append({'line': line_number, 'reason': str(error)})
    return totals, rejected

def write_csv(path, columns, rows):
    with Path(path).open('w', newline='', encoding='utf-8') as handle:
        writer = csv.DictWriter(handle, fieldnames=columns)
        writer.writeheader()
        writer.writerows(rows)

def main():
    totals, rejected = process_orders('orders.csv')
    write_csv('summary.csv', ['category', 'revenue'], [
        {'category': category, 'revenue': f'{amount:.2f}'}
        for category, amount in sorted(totals.items())
    ])
    write_csv('rejected.csv', ['line', 'reason'], rejected)
    print(f'{len(totals)} categories; {len(rejected)} rejected rows')

if __name__ == '__main__':
    main()

Show four automated tests (test_main.py)
import csv
import pytest
from main import process_orders

def make_csv(tmp_path, content):
    path = tmp_path / 'orders.csv'
    path.write_text(content, encoding='utf-8')
    return path

def test_valid_totals(tmp_path):
    path = make_csv(tmp_path, 'category,price,quantity\nBooks,10.00,2\n')
    totals, rejected = process_orders(path)
    assert str(totals['Books']) == '20.00'
    assert rejected == []

def test_invalid_price(tmp_path):
    path = make_csv(tmp_path, 'category,price,quantity\nBooks,bad,2\n')
    totals, rejected = process_orders(path)
    assert not totals
    assert len(rejected) == 1

def test_missing_column(tmp_path):
    path = make_csv(tmp_path, 'category,price\nBooks,10\n')
    with pytest.raises(ValueError):
        process_orders(path)

def test_empty_file(tmp_path):
    path = make_csv(tmp_path, '')
    with pytest.raises(ValueError):
        process_orders(path)

Install pytest in your virtual environment and run python -m pytest.

Common problems: FileNotFoundError means the CSV path is wrong. KeyError usually means a column name differs. ValueError can mean the input is not a valid number. Check the traceback, inspect the row and fix the cause instead of deleting the failing record.

Interview questions

  1. When should a list be used instead of a dictionary?
  2. What is the difference between print and return?
  3. What causes KeyError, ValueError and FileNotFoundError?
  4. Why should data validation happen before aggregation?
  5. How can a program be made safe to rerun?
Interview answer guidance

A list preserves an ordered sequence; a dictionary supports named key lookup. return passes a result to the caller, while print only displays it. KeyError is a missing mapping key, ValueError is an invalid value and FileNotFoundError is an unavailable path. Validation prevents invalid inputs from contaminating metrics. Repeatable programs use predictable inputs and overwrite or update outputs intentionally.
