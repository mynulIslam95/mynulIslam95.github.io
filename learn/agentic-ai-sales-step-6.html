State & recovery concepts

  • Possible States লিখো — research_pending, researching, draft_ready, awaiting_approval, approved, sending, sent, failed আর delivery_unknown। প্রতিটি Transition-এর Preconditions থাকবে।
  • Approval নির্দিষ্ট Draft Version, Recipient আর Content-এর সাথে Bind করো। User Content বা Recipient বদলালে Approval Invalidate হবে।
  • Checkpoint Computation Progress Save করে। External Email Send-এর Side Effect আলাদাভাবে track করতে হয়। Checkpoint দিয়ে Exactly-once Delivery ধরে নেওয়া যাবে না।
  • Send Request Timeout হলে Provider Accepted করেছে কি না Uncertain হতে পারে। delivery_unknown রেখে Message ID বা Idempotency Support দিয়ে Reconcile করো।
  • LangGraph Interrupt-এর Resume-এ Node Code আবার চলতে পারে। Approval Node-এর আগে Irreversible Action বসাবে না। Persistent Checkpointer আর Stable Workflow Identity রাখো।

Worked approval lab

lab_6.py

from dataclasses import dataclass
from hashlib import sha256

def digest(text: str) -> str:
    return sha256(text.encode("utf-8")).hexdigest()

@dataclass
class Draft:
    text: str
    approved_hash: str | None = None
    status: str = "draft"

    def approve(self) -> None:
        self.approved_hash = digest(self.text)
        self.status = "approved"

    def edit(self, text: str) -> None:
        self.text = text
        self.approved_hash = None
        self.status = "draft"

    def claim_send(self) -> str:
        if self.status != "approved" or self.approved_hash != digest(self.text):
            raise PermissionError("This draft version is not approved")
        self.status = "sending"
        return self.approved_hash

if __name__ == "__main__":
    draft = Draft("Hello, here is our relevant service.")
    draft.approve()
    draft.edit("Changed offer")
    try:
        draft.claim_send()
    except PermissionError:
        print("Edited draft requires new approval")
    else:
        raise AssertionError("Stale approval accepted")
    draft.approve()
    print(draft.claim_send())
    assert draft.status == "sending"

python lab_6.py চালালে Edit-এর পরে Approval Reject হবে, নতুন Approval-এর পরে sending হবে। এই Local Object Lab Persisted বা Concurrent Worker-safe নয়। Build Tasks-এ একই Check Database Transaction ও Durable Workflow-তে বসাবে।

Crash & concurrency drills

  • Approval Save-এর পরে Process বন্ধ করো। Restart-এ একই Draft Version দেখিয়ে Resume করো।
  • দুই Worker একই Send claim করুক। Only One Claim succeeds, এটা Integration Test-এ verify করো।
  • Provider Accept-এর পরে Local Commit fail করাও। Blind Retry-এর বদলে delivery_unknown ও Reconciliation দেখাও।
  • User Approval-এর পরে Recipient edit করো। Previous Approval ব্যবহার করে Send Attempt block হওয়া উচিত।
Expected recovery

Business State, Workflow Checkpoint আর External Provider State মিলিয়ে Resume করো। Draft Edit Approval বাতিল করে। Send Claim transactionally guarded হবে। Unknown Delivery-কে Success বা Safe-to-Retry বলা যাবে না যতক্ষণ Provider Evidence পাওয়া না যায়।

Consistency, side effects & crash recovery

এই Step-এর System Design Review-এ নিচের Decisions লিখবো আর Evidence দিয়ে ব্যাখ্যা করবো।

  1. State Machine-এ প্রতিটি Transition-এর Actor, Preconditions, Atomic Writes আর Retry Behaviour লিখো। Invalid Transition reject করো।
  2. Crash Matrix বানাও — Send-এর আগে, Provider Accept-এর পরে, Database Commit-এর আগে আর Commit-এর পরে Process Stop। প্রতিটি Case-এর Recovery Evidence রাখো।
  3. Delivery Semantics স্পষ্ট করো। Provider Idempotency Support না থাকলে Duplicate Send পুরোপুরি Eliminate করার Guarantee দেবে না, Unknown Delivery Review Policy রাখো।
  4. ADR-006-এ LangGraph Checkpoint বনাম Durable Business Workflow-এর প্রয়োজন compare করো। Features-এর প্রয়োজন থেকে Tool বেছে নাও।
