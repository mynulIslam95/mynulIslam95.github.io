The toolkit

If you forget the toolkit, the builder does not know the word lock.

Story

If you ask for a special lock, you must bring the toolkit. The first line of the note names the toolkit: #include <pthread.h>.

The builder also needs a flag: -pthread. If you forget the flag, the builder says it does not know the lock words.

POSIX semaphores often need #include <semaphore.h> and -lrt or -pthread on Linux.

The toolkit is not the story. It is the bag you carry so the story can run.

Practice. If you write pthread_create but you never include the toolkit, will the builder always succeed?

No. You must include the header. You must also pass -pthread when you call gcc.

Practice. Is gcc shop.c -o shop -pthread the builder command for a lock used by two workers?

Yes. -o shop names the tool. -pthread brings the thread toolkit.

The same story in C

You already know main. Here you only see the includes and the builder line. The lock story is OS3.

#include <stdio.h>
#include <pthread.h>
#include <semaphore.h>

/* gcc this.c -o this -pthread */

int main(void) {
  printf("toolkits are here\n");
  return 0;
}

stdio for print. pthread for workers and the key. semaphore for tickets. Compile with -pthread.

Practice. Does #include start the shop helper?

No. main still starts the helper. Include only brings words the builder must know.

Practice. After C1–C6, can you read a box, a helper, an address, a form, and a toolkit line?

Yes. That is enough C to open OS1. Process, lock, and mmap will add new words, still explained line by line.
