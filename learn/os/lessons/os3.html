Map · Floor 1 · OS3

One key for the drawer

The worker who took the key must give it back.

You need OS2. One key for one drawer. The worker who took the key must give it back.

Story

The cash drawer has one key. Only the worker who holds the key may open the drawer. That key is a mutex. Mutex means: one owner.

You lock, you change x, you unlock. If the other worker already has the key, you wait. You do not spin in front of the drawer: while (!free) { } burns the CPU.

The stretch that touches x is the critical section. Critical does not mean “important for the grade.” It means this stretch must not overlap.

A mutex does not stop deadlock. If A takes key 1 then key 2, and B takes key 2 then key 1, each mutex did its job and they still wait forever. Deadlock is OS5.

Practice. Does a mutex have an owner?

Yes. The worker who locked should unlock. A semaphore (OS4) has no owner.

Practice. Does a mutex also prevent deadlock?

No. It only says: one at a time on this key. A circle of two keys is a different problem.

The same story in C

#include <pthread.h>

int x = 0;
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;

void *worker(void *arg) {
  int i;
  for (i = 0; i < 1000; i++) {
    pthread_mutex_lock(&m);
    x = x + 1;
    pthread_mutex_unlock(&m);
  }
  return NULL;
}

m is the key, global so both lock the same key. lock, add 1, unlock. Only x = x + 1 is the critical section. &m is the paper (C4).

Practice. Should the mutex be global like x?

Yes. If each worker has its own mutex, they are not sharing one key.

Practice. Is the for-loop the critical section?

No. Only the lines that touch x while you hold the key. You must not hold the key for the whole 1000 if you do not need to — here we lock around each add.

SS2018 / WS2024 · true or false

“Mutexes avoid deadlocks.” Two threads add 1 to x. Why might x not be 2000?

Solution steps
  1. Mutexes avoid deadlocks: false. A mutex is one key. Deadlock is a circle.
  2. x = x + 1 is read, add, write. Both can read 10 and both write 11. Lost update.
  3. Fix: lock, add, unlock. Then x is 2000 if you also join.
