1. Files and directories

The terminal is the shop counter. You type a command. The shell starts a program, then comes back.

  • pwd — print working directory. Where am I?
  • cd — change directory.
  • ls — list names. ls -l — long: type, rights, size, date.
  • mkdir / rmdir — make / remove an empty directory.
  • cp copy. mv move or rename. rm delete a file.
  • cat dump a file. less / more page it. head start. tail end.

A new exam can swap the names. Own the job, not the slogan: copy, rename, list, go, show the start, show the end.

Short. Name at least four commands that work on files or directories.

pwd cd ls mkdir rmdir cp mv rm cat head tail. Four is enough.

Twist

True or false. mv can only move a file to another folder. It cannot rename.

No. Move and rename are the same job: change the name in the directory. mv old.c new.c is a rename.

2. Rights — ls -l and chmod

ls -l prints three groups of rwx: User (owner), Group, Others. r read, w write, x execute (for a directory: enter it).

The first character is the type: - file, d directory, l symlink.

Example: -rwxr-xr-- — a file. Owner may read, write, run. Group may read and run. Others may only read.

chmod changes those bits. Lecture homework: chmod u+x myscriptfile — add execute for the user, so you may run the script.

Exam trap: d-r-r---- is a directory with no x. You cannot cd into it. “Full of runnable programs” is the wrong story. Whether files inside can run is their bits.

True or false. File bits d-r-r---- mean a directory full of runnable programs.

No. d is a directory. There is no x, so you cannot enter it. Inner files have their own bits. This is a year-paper Y/N.

Twist

True or false. On a directory, x means “you may enter this folder,” not “this folder is a program.”

Yes. Same letter, different meaning on a directory. That is why the trap above works.

3. Find names, find text

Two different jobs:

  • find — walk the tree, match names (and more). “Where is this file?”
  • grep — search inside a file. “Which line has this word?”

Also: diff two files. sort lines. sed stream editor. awk pattern + action. expand / unexpand tabs vs spaces. You do not need to write awk in the written exam from this slide. You must not mix find and grep.

Twist

True or false. find is how you search the text inside a .c file.

No. Inside the file is grep. find looks for files in the tree.

4. Commands that touch processes

  • ps / htop — what is running.
  • kill — send a signal to a PID. Often SIGTERM, so it usually dies. Not the only signal. “kill can only terminate” is false. That Y/N already lived with fork on OS12.
  • nohup — start a process that does not die when the terminal closes.
  • renice — change priority of a process that is already running. Lab 2 used nice at start: higher nice = nicer to others = less CPU.
  • sleep — wait. The process is Blocked, not Ready. Lab 2: usleep.
  • time — how long a command took.
  • man — the manual page. login / logout.

Also on the slide: git, make, tee (copy the stream to a file and still pass it on).

True or false. kill can only terminate a process.

No. You name a signal. Default often ends it. A handler can catch SIGINT. You can also signal the parent.

Twist

True or false. nohup ./job can keep running after you close the terminal.

Yes. That is the point of the lecture line: independent of the terminal, no hangup.

5. Redirect and pipe

Every process has three streams: 0 stdin, 1 stdout, 2 stderr.

  • cmd > file — stdout replaces the file.
  • cmd >> file — stdout appends.
  • cmd 2> file — stderr replaces the file. Write 2> as one token. A space between 2 and > is a trap: then 2 is an argument and you only redirected stdout.
  • cmd 2>> file — stderr appends.
  • cmd < file — stdin from a file.
  • cmd1 | cmd2 — stdout of the first becomes stdin of the second. A pipe. Bytes come out FIFO.
Twist

True or false. cmd 2> err.txt writes the normal printout into err.txt.

No. 2> is stderr. Normal printout is stdout (1). Errors go to the file. Prints still hit the screen unless you also redirect 1.

True or false. Bytes in a pipe come out in FIFO order.

Yes. First byte in, first byte out. Year-paper Y/N. A pipe is a kernel queue, not a file you seek in.

6. Shell variables

A name: letters, digits, underscore. Digits not at the start. Assign with = and no spaces: myVar=4711. Read with $: echo $myVar.

Expansion: a string with a placeholder is filled at run time. Lecture: date +%Y_%m_%d → 2024_10_08. Used in the backup script for a folder name.

Twist

True or false. myVar = 4711 (spaces around =) is a valid assignment.

No. The shell then thinks myVar is a command. Write myVar=4711 with no spaces.

7. Special variables

  • $1, $2, … — arguments of the script.
  • $# — how many arguments.
  • $* / $@ — all arguments. Quoted "$@" keeps words intact.
  • $? — exit status of the last command. 0 usually means ok.
  • $$ — PID of this shell.
  • $! — PID of the last background job (&).
  • $PATH — directories the shell searches for commands.

Do not mix $? and $$. One is a status. One is a process id.

Short. Name at least three special shell variables and what they mean.

$1 first argument. $# count. $? last status. $$ this shell’s PID. $PATH search list. Three is enough.

Twist

True or false. $$ is the exit status of the last command.

No. Status is $?. $$ is the PID of the shell that is running now.

8. How a script actually runs

First line: #! /bin/sh — shebang. The kernel uses that program to run the file. History: sh 1978, then csh, ksh, zsh, ash. Today’s Linux default is bash (Bourne Again). Sometimes /bin/sh is a symlink to bash.

To run it:

  1. Write it (nano myscriptfile).
  2. chmod u+x myscriptfile — user may execute.
  3. ./myscriptfile — the dot means this directory.

Why ./? Because . is usually not in $PATH. If you type only the name, the shell looks in /usr/bin and friends, not here. That is a safety rule, not a bug.

Twist

True or false. After chmod u+x ./job, typing job (no ./) always runs it, because it is executable.

No. Execute bit is necessary, not enough. The shell still searches $PATH. Current directory is usually missing. Use ./job.

9. if, test, for

if condition; then …; else …; fi

Useful tests:

  • test -f name — that file exists (regular file).
  • test -d name — that directory exists.
  • Strings: test zk1 = zk2
  • Numbers: -eq -ne -lt -le -gt -ge
  • ! not, -a and, -o or

Homework on the slide: a script exam that takes a percentage 0…100. Print passed if it is above 50, else failed. So 50 is failed.

case / esac — pick a branch by a word (weekday homework).

for i in list; do …; done. Also while and until.

Lecture trap. What does this do?

k=".c"
for i in *$k
do
  j=${i%$k}
  make $j
  rm -fv ${j}.o
done

For each file ending in .c, strip the suffix, run make on that name, delete the .o. ${i%$k} means: take i, remove the shortest suffix that matches .c.

True or false. The lecture exam script prints passed for 50 percent.

No. The slide says above 50. 50 is not above 50. Print failed.

Short. In one sentence: what does the for i in *.c / make script do?

For every .c file, strip .c, run make on that name, remove the object file.

10. gcc and argv

Compile: gcc -o mycfile mycfile.c then ./mycfile.

Without -o mycfile, the executable is named a.out. That default is an exam favourite.

Command-line arguments in C:

int main(int argc, char *argv[])

argc is the count. argv[0] is the program name as typed. argv[1] is the first real argument. For ./argvdemo one two three: argc is 4, not 3.

UNIX treats many things as a file: disk files, devices, pipes. Open, read, write, close. That Y/N sits in the exam hall with this lecture.

True or false. If you forget -o, gcc still builds a program named a.out.

Yes. Default name. Then you run ./a.out.

Twist

True or false. For ./argvdemo one two three, argc is 3 because there are three words after the program.

No. Count includes argv[0]. 1 + 3 = 4. The loop on the slide starts at i = 1, so it prints the three words and skips the name.

Lecture 06 · rights · also exam-hall Y/N

What does ls -l show in the nine rwx bits? Why is d-r-r---- not “a directory of runnable programs”? How do you make a script executable for yourself?

Answer and steps
  1. Three groups: owner, group, others. Each group: read, write, execute.
  2. First character is the type: d directory, - file.
  3. On a directory, x means enter (cd). d-r-r---- has no x, so you cannot enter. Inner files have their own bits. Write false for “runnable programs.”
  4. chmod u+x myscriptfile adds execute for the user. Then ./myscriptfile.

Lecture 06 · redirect and pipe

Write the six redirections from the slide. What is the difference between > and 2>? What does a pipe do?

Answer and steps
  1. > stdout, replace. >> stdout, append.
  2. 2> stderr, replace. 2>> stderr, append. No space between 2 and >.
  3. < stdin from a file.
  4. cmd1 | cmd2: stdout of the first is stdin of the second. FIFO. Not the same as writing a file.

Lecture 06 · why ./script

You wrote a script, set the execute bit, typed the name, and got “command not found.” Why? How do you run it?

Answer and steps
  1. The shell searches $PATH. Current directory is usually not on that list. Safety: you do not run a random ls from this folder by accident.
  2. Run ./myscriptfile. The ./ names this folder, so PATH is not asked.
  3. You still need chmod u+x once, and a shebang #! /bin/sh at the top is the clean way.

Lecture 06 · gcc and argvdemo.c

How do you compile mycfile.c? What if you omit -o? For ./argvdemo one two three, what is argc, and what is argv[0]?

Answer and steps
  1. gcc -o mycfile mycfile.c then ./mycfile.
  2. Without -o, the file is a.out. Run ./a.out.
  3. argc = 4. argv[0] is ./argvdemo (the name as typed). argv[1..3] are one, two, three. The slide’s loop starts at 1, so it prints the three words.

Lecture 06 · backup script and date

What does the lecture backup script do, line by line?

datum=$(date +%Y_%m_%d)
mkdir backup_$datum
cp $HOME/*.c backup_$datum
Answer and steps
  1. date +%Y_%m_%d expands to a string like 2024_10_08. Stored in datum.
  2. mkdir backup_2024_10_08 (that day’s name).
  3. Copy every .c file from the home directory into that folder. $HOME is the home path. *.c is expanded by the shell before cp runs.
  4. It does not compile. It does not copy headers unless they end in .c.

Lecture 06 · for + make · “what is going on here?”

k=".c"; for i in *$k; do j=${i%$k}; make $j; rm -fv ${j}.o; done

Answer and steps
  1. *$k is *.c: each C source in this folder.
  2. ${i%$k} removes the suffix .c. So hello.c becomes hello.
  3. make hello builds that program (using a makefile or default rules).
  4. rm deletes hello.o. The executable can stay.
  5. If there is no .c file, *.c may stay as the literal string. Then the loop is one broken step. Say that if he asks “and if the folder is empty?”

Lecture 06 homework · exam pass/fail

Write a script that takes a percentage 0…100 and prints passed or failed. Above 50 is passed.

Answer and steps
  1. Shebang. Use $1 as the percentage.
  2. if test "$1" -gt 50; then echo passed; else echo failed; fi
  3. -gt is numeric greater-than. 50 is not greater than 50 → failed.
  4. Call: ./exam 70 → passed. ./exam 50 → failed.

Signals and priority · kill / nohup / renice (with Lab 2)

kill only terminates? What is nohup? What does a higher nice value mean?

Answer and steps
  1. kill sends a signal to a PID. Default often ends the process. Other signals exist. Write false for “only terminate.”
  2. nohup: hangup from closing the terminal does not kill the job.
  3. Higher nice / renice = nicer to others = less CPU when both burn the core. Lab 2 lives on OS1.
