Map · Floor 1 · OS5

Two keys, both wait

A has key 1. B has key 2. Nobody can move.

You need OS3 and OS4. Deadlock is a circle of waiting, not “the mutex failed.”

Story

Four cars in a crossing. Each sits in one square and needs the next. Nobody can reverse. If they wait in a circle, they stand forever. That is deadlock.

Four conditions. 1. Only one may use it. 2. Hold and wait: keep what you have, ask for the next. 3. No snatch: the OS will not pull the tool out of a hand. 4. Circular wait. The first three make deadlock possible. The circle makes it exist. Remove any one of the four, and deadlock cannot stay.

Jazz takes the organ then the synth. Classical takes the synth then the organ. Drive them until Jazz holds organ and waits for synth, Classical holds synth and waits for organ. That is the circle. One organ, one synth: the picture of a cycle is deadlock.

If a tool has several copies, a cycle on the drawing is not enough. Someone outside might finish and give one back. Then you need the detection numbers, not only the drawing.

Three jobs the OS can do. Prevention: design so one condition cannot happen (same order). Avoidance: Banker's — pretend to grant, can everyone still finish? Detection: grant freely, later find who is stuck now.

Need is the future (Claim minus what you hold). That is Banker's. Request is what they want now. That is detection. Do not mix the tables. Unsafe is not “stuck this second.” Unsafe means you might get stuck later, so you deny.

Practice. Does a mutex prevent deadlock?

No. A mutex is condition 1 (only one may use it). The circle can still form with two mutexes in opposite order.

Practice. If both programs take organ then synth, can this circle still form?

No. Same order. The circle cannot form. That is prevention.

Practice. Is unsafe the same as deadlock now?

No. Unsafe is Banker's future. Deadlock now is detection.

Worked numbers · Banker's

P1 requests (1, 0). Show every Work step.

Solution steps
  1. Request (1,0) fits P1 Need (1,0) and fits free (1,0). Pretend: P1 now holds (1,1). Free becomes (0,0).
  2. P1 Need is now (0,0), which fits Work (0,0). Mark P1 finished. Work += (1,1) → (1,1).
  3. P2 Need (1,1) now fits. Mark P2. Everyone finished → GRANT.
  4. If after pretend nobody’s Need fits, DENY. Write every Work vector, not only the last line.

SS2022 jazz / SS2020 tape-printer / SS2025 robots

One robot takes T then P. The other takes P then T. One of each. Four conditions, prove deadlock, one fix.

Solution steps
  1. Name the four conditions in full sentences.
  2. Drive until A holds T and waits for P, B holds P and waits for T.
  3. Graph: arrow from process to the resource it waits for, arrow from resource to the holder. Cycle. One instance each → this cycle is deadlock.
  4. Fix: both take T then P. Do not answer “use a mutex.”

SS2025 · Banker's vs detection

What is the difference between Need and Request? Unsafe versus deadlock?

Solution steps
  1. Need = Claim − Allocation. Future. Banker's pretends to grant, then asks if everyone can still finish. If not: unsafe, deny.
  2. Request Q = what they want now. Detection. No pretend future. Unmarked names are deadlocked now.
  3. Do not put Need in the detection table. Do not put Q in Banker's.
