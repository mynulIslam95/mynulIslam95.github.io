Map · Floor 1 · OS6

A window both shops can see

The violin board sits in a shared window.

You need C4, C5, and OS4. Two shops, one window.

Story

Two different shops need to see the same violin board. You put the board in a window both can look through. That window is shared memory.

Shared memory is not a lock. It only makes the same bytes visible. You still put a mutex or a semaphore on that page.

The rental creates a named page with shm_open, gives it a size with ftruncate, then mmap with MAP_SHARED so the other shop sees the writes. Then sem_init(s, 1, 20).

The student opens the same name, no O_CREAT, read-write, because sem_wait writes the counter. Read-only can crash.

Practice. Is shared memory a synchronization tool by itself?

No. It only shares bytes. You still need a mutex or a semaphore on that page.

Practice. Must the student open the page read-write to call sem_wait?

Yes. wait subtracts one. That is a write.

The same story in C

#include <fcntl.h>
#include <sys/mman.h>
#include <semaphore.h>
#include <unistd.h>

int main(void) {
  int fd = shm_open("/pool", O_CREAT | O_RDWR, 0666);
  ftruncate(fd, sizeof(sem_t));
  sem_t *s = mmap(NULL, sizeof(sem_t),
                  PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
  close(fd);
  sem_init(s, 1, 20);
  pause();
  return 0;
}

O_CREAT: rental goes first. ftruncate: without a size there is no room. MAP_SHARED: the student must see writes. sem_init 1,20. pause, not an empty loop.

int main(void) {
  int fd = shm_open("/pool", O_RDWR, 0);
  sem_t *s = mmap(NULL, sizeof(sem_t),
                  PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
  close(fd);
  int i;
  for (i = 0; i < 5; i++) {
    sem_wait(s);
    sleep(1);
    sem_post(s);
  }
  return 0;
}

Student: no O_CREAT. O_RDWR. Same name /pool. Five take-play-return.

SS2022 Task 1 / SS2020 travel agency

Why shared memory? What if pshared is 0? Why not mmap read-only for the student?

Solution steps
  1. Students are other programs. They do not share the rental’s heap.
  2. pshared 0: each program has its own counter of 20. Forty violins in the world.
  3. Read-only: sem_wait must write. It can crash. Open O_RDWR, PROT_READ | PROT_WRITE.
  4. Rental must not burn the CPU: pause(), not while(1){}.
