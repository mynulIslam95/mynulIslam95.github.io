Map · Floor 1 · OS1

Copy the whole shop

Two buildings. Each has its own money box. Then year questions with steps.

You need C1–C4. A process is a running copy of a program.

Story

A recipe on the shelf is a program. When the building starts it, it becomes a process: one running shop, with its own number (PID) and its own money box.

You can copy the whole shop. That copy is fork. Now there are two buildings. Each has its own money. If shop A writes 5, shop B still has the old number.

In the child shop, fork returns 0. In the parent shop, it returns the child’s PID. If it fails, it returns −1.

exec does not copy the shop. It throws away the work inside the same PID and loads a new recipe. After the child runs ls, you still have two processes, not three.

If the child closes and the parent never calls waitpid, a tiny zombie slot stays. waitpid frees it.

Five states of one shop: New (the notebook is not ready), Ready (it wants the CPU), Running (it is on the core), Blocked (it waits for sleep, a pipe, or a ticket), Exit.

Practice. After fork, can the two shops see each other’s money box?

No. Each has a copy. Threads in one shop would share. That is OS2.

Practice. Does exec make a third process?

No. Same PID, new program. The number of processes does not go up.

Practice. Does waitpid stop a child staying a zombie?

Yes. The parent collects the exit code. The kernel can drop the tiny slot.

The same story in C

#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
  int x = 10;
  pid_t p = fork();
  if (p == 0) {
    x = 20;
    printf("child x=%d\n", x);
    return 0;
  }
  printf("parent x=%d\n", x);
  waitpid(p, NULL, 0);
  return 0;
}

x starts 10. fork copies the shop. Child sets x to 20 and prints 20. Parent still prints 10, then waitpid.

Practice. Does the parent print 10?

Yes. The parent’s x was never set to 20. That write happened in the other shop.

Practice. Can you tell parent from child by a global you set before fork?

No. Both copies start with that same global. You tell them apart with the return value p. “You cannot use variables” is the wrong sentence: p is a variable.

Lab 2, same shop

Parent prints A, child prints B, in a tight loop. You hope to see ABAB. You often see AAAA then BBBB. printf stores letters in a buffer. The OS sees a chunk, not each time slice. Higher nice means the process is nicer to others: less CPU. usleep puts the shop in Blocked, not Ready. A lock file can stay after a crash. fcntl is a lock the kernel forgets when the process dies.

SS2018 / many years · true or false

After fork, can the two processes use each other’s heap? Does exec create an extra process? Can two forks make a process its own grandfather? Does a parent have at most one child?

Solution steps
  1. Heap after fork: no. Two copies. Write false for “they can use each other’s heap.”
  2. exec: same PID, new program. Write false for “exec creates an extra process.” Write true for “after exec there are as many processes as before.”
  3. Fork only makes children, down the tree. Grandfather: false.
  4. A parent may have many children. “At most one” is false. waitpid true for zombies.

Lab 2 · WS2024

You raise nice, both use printf, then you add usleep. Why is a lock file a bad lock?

Solution steps
  1. Higher nice → lower priority → less CPU if both burn the CPU.
  2. printf buffers, so the screen is chunks, not time slices. Say the buffer, not “the scheduler is unfair.”
  3. usleep is Blocked, not Ready. They stop fighting for the core.
  4. A lock file can remain after a crash. fcntl is a kernel lock. F_SETLKW waits.
