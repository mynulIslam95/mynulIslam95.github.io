Map · Floor 1 · OS4

Twenty violins

A number on the wall. Not a key. Anyone may take one.

You need OS3 and C5. Twenty tickets, not one key.

Story

On the wall hang twenty violins. The number on the wall is a semaphore: a counter. There is no owner. Anyone may take one. Anyone may put one back.

sem_wait takes one ticket, or waits if there are none. sem_post gives one back and can wake a waiter. Shop A may take. Shop B may return.

If the people taking tickets are workers in one shop (threads), they already share. sem_init(s, 0, 10) — the 0 means only this process. That is the 2018 gallery: at most 10 visitors, 500 visitor threads.

If the people taking tickets are other programs, they cannot see a global in the first program. The counter must sit in a window both can see (OS6), and the second argument of sem_init must be 1. If you pass 0, each program has its own 20. The school thinks it has 20 violins and hands out 40.

A mutex is the wrong tool here. A mutex is one key, not twenty tickets.

Practice. Is a mutex the right tool for 20 violins?

No. One key cannot count 20. You need a counter.

Practice. If students are other programs, must pshared be 1?

Yes. 1 means other processes may use this object. 0 means only this process.

The same story in C

Two programs. Start the rental first, then a student. Both compile with -pthread. The window itself is OS6. Here you see the tickets.

/* rental — create the counter of 20, then sleep */
sem_init(s, 1, 20);
pause();   /* wait in the kernel. while(1){} burns the CPU */

/* student — five lessons */
for (i = 0; i < 5; i++) {
  sem_wait(s);   /* take a violin; Blocked if none left */
  sleep(1);      /* play */
  sem_post(s);   /* give it back */
}

sem_init: 1 = other programs, 20 = free violins. pause does not burn the CPU. wait takes, post returns. Student opens the page read-write because wait writes the counter.

Practice. Is Pause20Hours 22000 seconds?

No. sleep(20 * 3600) is 72000 seconds.

Practice. If 20 violins are out, does student 21 wait instead of spin?

Yes. sem_wait blocks. That is Blocked, not a busy loop.

SS2022 · music school (same skeleton: SS2020 holidays, SS2025 robots)

A rental process owns 20 violins. Later, other programs (students) start. Five exercises: take, play, return. Never more than 20 out. No busy wait. Rental may live forever.

Solution steps
  1. Actors: rental program + student programs. Not threads of one process.
  2. Shared thing: a counter of 20, not one key. So counting semaphore, not mutex.
  3. They cannot see the rental’s heap. Put the semaphore in shared memory (OS6). sem_init(s, 1, 20).
  4. Take = sem_wait. Return = sem_post. Rental = pause(). Student mmap must be read-write.
  5. 2020/2025: four counters in one struct (C5), same skeleton.

SS2018 · gallery

At most 10 visitors at once. 500 visitor threads of one process.

Solution steps
  1. Same shop: threads. They already share. No shm_open required.
  2. sem_init(s, 0, 10). The 0 is pshared: only this process. 10 is the count.
