Map · Floor 2 · OS8

Telnet and a bell

xinetd owns the port. Your program reads 0 and writes 1.

Lab 3 and the network lecture. You need OS1 (Blocked, fork).

Story

A socket is an end of a talk. TCP is a connection. Lost packets are sent again. UDP is a datagram, no connection.

If you are the client, you know the host and the port. You connect, write, read, close. You do not bind a famous port.

If you write the server, you bind, listen, then loop on accept. accept waits until a client finishes the handshake. It gives you a new file for that client. The original socket keeps listening.

If customers telnet in, and each connection should start your program: that is xinetd. xinetd already owns the port. It starts your program and gives the open connection as file 0 and 1. Your C only reads 0 and writes 1. If you write socket/bind/accept in this program, you answered the wrong question.

Config: port, path, TCP, nowait, UNLISTED if the name is not in services. Reload with SIGHUP. Test with telnet. Wireshark: SYN, SYN-ACK, ACK.

Lab 3.1: a program prints a file again and again. You edit the file. You send SIGUSR1. The signal is a bell, not the new text. The handler only sets a flag. You open the file in the main loop, not inside the handler.

Lab 3.2: message queue. Empty queue: mq_receive blocks. That process is Blocked, not Ready, not spinning.

Practice. When xinetd starts SingleHoliday, does SingleHoliday call bind?

No. xinetd already accepted. The program reads 0 and writes 1.

Practice. Is accept used by a server to take a client’s connection?

Yes — if you write the server yourself. Not if xinetd already did it.

Practice. Does SIGUSR1 contain the new file text?

No. The file contains the text. The signal says “look again.”

The same story in C

int main(void) {
  char buf[256];
  int n = read(0, buf, sizeof buf);
  int log = open("log.txt", O_WRONLY | O_CREAT | O_APPEND, 0666);
  write(log, buf, n);
  close(log);
  return 0;
}

xinetd program: no sys/socket.h. stdin is the client. You write a log. Port lives in the xinetd config.

volatile sig_atomic_t reload = 0;
void handler(int sig) { reload = 1; }

Handler only sets a flag. No fopen, no printf here. Main loop sleeps, checks the flag, then reads the file.

SS2020 / SS2025 Task 3 · telnet

Customers telnet to port 6000. Each connection starts SingleHoliday. Which service? Bind? Reload? Test?

Solution steps
  1. Service: xinetd (internet super-daemon).
  2. SingleHoliday does not call socket, bind, listen, or accept.
  3. Reload: SIGHUP / sudo service xinetd reload. That rereads config, it does not rerun your log loop.
  4. Test: telnet ip 6000. Wireshark: SYN, SYN-ACK, ACK, then data.

SS2024 primes · client vs global server

Send the prime to a host and port. Then let the world telnet in.

Solution steps
  1. Send to a host: you are a TCP client. socket, connect, write. No bind of a well-known port.
  2. World telnets in: xinetd, or bind/listen/accept if the paper did not say super-daemon.
