1.5.1 try/except and error categories

User "oops" লিখেছে, কিন্তু program whole number চায়। int("oops") fail করবে। Expected input error handle করবো; unrelated programming bugs চেপে রাখবো না। try-এর code attempt হয়, matched exception হলে except block চলে।

Code-টা run করি

def parse_amount(raw):
    try:
        amount = int(raw)
    except ValueError:
        return "invalid input"
    return amount

print(parse_amount("12"))
print(parse_amount("oops"))

Output

12
invalid input

কীভাবে এই result হলো?

  1. "12" conversion succeeds, except চলে না, amount 12 return হয়।
  2. "oops"-এ int ValueError দেয়; execution matched handler-এ যায়।
  3. Function এই ছোট UI example-এ error label return করছে। Reusable calculation API-তে mixed return এড়িয়ে ValueError raise করা ভালো হতে পারে।
এখানে যেটা ভুল হতে পারে

সব error-এ 0 return করলে genuine zero ও malformed data মিশে যায়। except Exception: pass unexpected bug-ও লুকাতে পারে।

raise ValueError("Positive amount required") caller-কে invalid value জানায়। finally cleanup code success/failure দুই অবস্থাতেই চালাতে পারে। except ValueError as error caught error bind করে; নতুন error raise ... from error করলে original cause preserve হয়। try-এর else block শুধু exception না হলে চলে।

এবার তুমি বদলে দেখো

Function-এ int-এর পরে amount <= 0 হলে ValueError raise করো। Existing try block-এর ভিতরে রাখলে কী হবে?

Reasoning মিলিয়ে দেখো

একই ValueError handler catch করবে। যদি invalid value-এর reason caller-কে আলাদা দিতে চাও, parse ও business validation আলাদা করো বা specific messageসহ raise করো।

1.5.2 pathlib and context managers

Receipt save করে পরে read করবো। Path file-এর location represent করে, open actual resource খুলে দেয়। নিচের temporary folder code শেষ হলে clean হয়, তাই নিজের files overwrite করবে না।

Code-টা run করি

from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    path = Path(folder) / "receipt.txt"
    with path.open("w", encoding="utf-8") as handle:
        handle.write("Penny: EUR 12")
    with path.open(encoding="utf-8") as handle:
        receipt = handle.read()
    print(receipt)

Output

Penny: EUR 12

কীভাবে এই result হলো?

  1. Path(folder) / filename cross-platform path join করছে।
  2. "w" mode file লিখতে খুলেছে; write text পাঠিয়েছে। First with শেষ হলে handle close হয়েছে।
  3. দ্বিতীয় with default read mode-এ content পড়েছে। read() returned string receipt-এ আছে।
এখানে যেটা ভুল হতে পারে

"w" existing file truncate করে। File handle variable file-এর contents না। Relative path current working directory থেকে resolve হয়, script folder থেকে automatically নয়।

with cleanup handle করে, তাই file close করতে ভুল হওয়ার chance কমে। গুরুত্বপূর্ণ report update-এ same-directory temporary file + replace useful pattern; atomic rename একা backups বা power-loss durability guarantee করে না।

এবার তুমি বদলে দেখো

receipt.txt-এর বদলে report.txt দিলে কোথায় file হবে? encoding explicit কেন?

Reasoning মিলিয়ে দেখো

একই temporary folder-এ নতুন নাম হবে। UTF-8 explicit রাখলে Bangla text different machines-এ consistent encoding-এ read/write করা যায়।

1.5.3 CSV parsing

CSV-এর একটি merchant name-এ comma আছে: "Shop, Berlin"। Manual split(",") করলে field ভেঙে যাবে। DictReader header names দিয়ে প্রতিটি row-এর dict দেয়। এখানে disk file-এর বদলে StringIO দিয়ে text-কে file-like stream বানাচ্ছি।

Code-টা run করি

import csv
from io import StringIO

source = StringIO('id,merchant,amount\nT1,"Shop, Berlin",12\n')
reader = csv.DictReader(source)
for row in reader:
    print(row["merchant"])
    print(type(row["amount"]).__name__)
    print(int(row["amount"]) + 1)

Output

Shop, Berlin
str
13

কীভাবে এই result হলো?

  1. Header থেকে id, merchant ও amount keys এসেছে।
  2. Quoted comma parser merchant field-এর অংশ হিসেবে রেখেছে।
  3. CSV amount text "12"। type(...).__name__ type object-এর readable name দেয়। int conversion-এর পরে যোগ করা যাচ্ছে।
এখানে যেটা ভুল হতে পারে

CSV parser field values validate করে না। Missing header, empty amount আর invalid number আলাদা problem। Row বাদ দিলে row number ও safe reason রাখো।

Real file open করতে path.open(encoding="utf-8", newline="") ব্যবহার করো। csv module newline handling করবে। Source data trusted না হলে size/field limits-ও প্রয়োজন অনুযায়ী নির্ধারণ করতে হয়।

এবার তুমি বদলে দেখো

Amount oops দিলে int conversion কোথায় fail করবে? শুধু bad row reject করতে try কোথায় রাখবে?

Reasoning মিলিয়ে দেখো

Loop-এর ভিতরে conversion ও row validation try block-এ রাখবে। Header missing হলে file-level failure হিসেবে আগে reject করবে।

1.5.4 JSON serialization

Report অন্য service-এ পাঠাতে Python dict যথেষ্ট না, একটা transferable text representation দরকার। JSON encode/decode করি। dumps-এর s string বোঝায়, dump file-like target-এ write করে।

Code-টা run করি

import json

report = {"currency": "EUR", "spent_cents": 1975, "valid": True}
text = json.dumps(report, sort_keys=True)
print(text)
restored = json.loads(text)
print(restored["spent_cents"])

Output

{"currency": "EUR", "spent_cents": 1975, "valid": true}
1975

কীভাবে এই result হলো?

  1. dumps dict থেকে string তৈরি করেছে; JSON boolean true lowercase।
  2. sort_keys শুধু predictable display order-এর জন্য। Business meaning key order-এর উপর depend করে না।
  3. loads থেকে dict ফিরে এসেছে, তাই key দিয়ে spent_cents পাওয়া যায়।
এখানে যেটা ভুল হতে পারে

JSON text আর Python dict আলাদা types। Untrusted text decode করতে eval() ব্যবহার করবে না। Decimal/datetime/custom class default encoder নিজে বুঝবে না; explicit data representation লাগবে।

Money integer cents বা decimal string হিসেবে পাঠানো যায়। Real input-এ accepted fields, types ও maximum sizes validate করবে। Non-finite floats আটকাতে json.dumps(..., allow_nan=False) useful।

এবার তুমি বদলে দেখো

spent_cents-এর value "1975" text করে encode/decode করো। ফিরে এসে int থাকবে কি?

Reasoning মিলিয়ে দেখো

না, JSON string type preserve হবে। Arithmetic-এর আগে contract অনুযায়ী validate/convert করতে হবে।

1.5.5 Decimal for money

€12.50-এর মধ্যে 1250 cents আছে। Binary float দিয়ে exact monetary arithmetic নিয়ে assumptions করা ঠিক না। Decimal string থেকে decimal value রাখে। আমরা finite, positive, whole-cent amount accept করবো। আগে basic conversion দেখি।

Code-টা run করি

from decimal import Decimal

amount = Decimal("12.50")
fee = Decimal("0.25")
net = amount - fee
print(net)
print(int(amount * 100))

Output

12.25
1250

কীভাবে এই result হলো?

  1. String "12.50" থেকে Decimal তৈরি, আগে float বানানো হয়নি।
  2. দুই Decimal subtract করলে 12.25 পাওয়া যায়।
  3. 100 দিয়ে multiply করলে 1250.00 cents; whole-cent value হওয়ায় int conversion safe।
এখানে যেটা ভুল হতে পারে

int(Decimal("1.001") * 100) করলে fraction silently truncate হবে। Conversion-এর আগে whole-cent rule validate করতে হবে। Decimal NaN/Infinity-ও represent করতে পারে, তাই finite check প্রয়োজন।

এই Module-এর money parser input length/range bound করে, তারপর is_finite(), sign ও fractional cents check করে। Display-এ দুই decimal দেখানো validation না। Fraction rounding দরকার হলে rounding policy business requirement থেকে নির্ধারণ করো, নিজের মতো কেটে দিও না।

এবার তুমি বদলে দেখো

Decimal(0.1) আর Decimal("0.1") print করে compare করো। কেন আলাদা হতে পারে?

Reasoning মিলিয়ে দেখো

0.1 literal আগে binary float হয়েছে, Decimal সেই approximation capture করে। String form সরাসরি intended decimal value দেয়।

Debugging: কোথা থেকে শুরু করবে?

File পাওয়া যাচ্ছে না? Path.cwd() আর resolved path দেখো। CSV total wrong? Header, quote, empty field ও conversion check করো। Error message-এ full customer record, password বা token log করবে না।

Practice 1: CSV Import with Rejections

CSV-এর amount_cents whole positive integer হতে হবে। Good rows total করো, bad row numbers আলাদা রাখো।

Hint

DictReader-এ enumerate start=2 দাও, কারণ header row 1।

See Solution

প্রতিটি row-কে আলাদাভাবে validate করো; একটি bad row পুরো batch থামাবে না।

Solution-টা বুঝে নিই

Conversion ও positive-value check একই row-এর try block-এ। Bad value-এ handler row number record করে continue করেছে। তাই good rows total 1975।

import csv
from io import StringIO
source = StringIO('id,amount_cents\nT1,1250\nT2,oops\nT3,-2\nT4,725\n')
total = 0
rejected = []
for line, row in enumerate(csv.DictReader(source), start=2):
    try:
        amount = int(row['amount_cents'])
        if amount <= 0:
            raise ValueError('Nonpositive amount')
    except (ValueError, TypeError):
        rejected.append(line)
        continue
    total += amount
print('Check:', total == 1975)
print('Check:', rejected == [3, 4])

Output

Check: True
Check: True

নিজের কাজ মিলিয়ে দেখো

Malformed file header batch-level error, bad value row-level error। Missing amount_cents header আলাদা করে reject করার check নিজে যোগ করো।

Practice 2: Safe Money to JSON

Positive euro amount string থেকে integer cents return করো। NaN, Infinity, blank, negative আর fractional cent reject করো। Result JSON encode করো।

Hint

Decimal finite check comparison-এর আগে; float conversion এড়াও। এই exercise input length 30 characters limit রাখো।

See Solution

Bound input, parse, finite/range check, cent validation, তারপর integer conversion।

Solution-টা বুঝে নিই

Decimal string input থেকে এসেছে। Finite/range check-এর পরে whole-cent equality check। তারপর int conversion, তাই fractional cents silently cut হয়নি।

import json
from decimal import Decimal, InvalidOperation

def to_cents(raw):
    text = raw.strip()
    if not text or len(text) > 30:
        raise ValueError('Invalid input length')
    try:
        value = Decimal(text)
    except InvalidOperation as error:
        raise ValueError('Invalid amount') from error
    if not value.is_finite() or not 0 < value <= Decimal('1000000'):
        raise ValueError('Amount outside allowed range')
    if value * 100 != (value * 100).to_integral_value():
        raise ValueError('Fractional cents')
    return int(value * 100)
print('Check:', to_cents('12.50') == 1250)
for bad in ('NaN', 'Infinity', '', '-1', '1.001'):
    try:
        to_cents(bad)
    except ValueError:
        pass
    else:
        raise AssertionError(f'Accepted invalid input: {bad}')
print('Check:', json.loads(json.dumps({'amount_cents': to_cents('7.25')}))['amount_cents'] == 725)

Output

Check: True
Check: True

নিজের কাজ মিলিয়ে দেখো

Good amount round-trip হবে। প্রতিটি invalid value ValueError দেবে।
