1.5 Exceptions, Files, CSV & JSON

A finance team gives you a CSV with invalid amounts. Some files are missing and the final report needs to be JSON. Handle expected input errors explicitly so a faulty report cannot pass as a success.

1.5.1 try/except and error categories

The program expects a whole number and receives "oops". int("oops") raises an exception. Handle the expected input failure and let unrelated bugs surface. try runs the code. If an exception matches, the except block handles it.

Run the code

def parse_amount(raw):
    try:
        amount = int(raw)
    except ValueError:
        return "invalid input"
    return amount

print(parse_amount("12"))
print(parse_amount("oops"))

Output

12
invalid input

How it works

  1. Converting "12" succeeds, so the function returns 12.
  2. Converting "oops" raises ValueError and runs the matching handler.
  3. This small UI example returns an error label. A reusable calculation function can raise ValueError to keep its successful return type consistent.
Common mistake

Returning 0 for every error makes malformed data look like a real zero. except Exception: pass can also hide an unexpected bug.

raise ValueError("Positive amount required") signals an invalid value to the caller. finally runs cleanup whether the operation succeeds or fails. except ValueError as error binds the caught exception. Use raise ... from error to preserve the original cause. try runs only if the try block completes without an exception.

Try a change

After int(), raise ValueError if amount <= 0. What happens if that check is inside the existing try block?

Check your reasoning

The same handler catches it. Separate parsing from business validation or raise a specific message if the caller needs to know the reason.

When Python shows a traceback, read the last line for the error type and message. Then look for the line from your own file just above it. See a traceback example.

Raise an error when an inspection rule fails

The site needs at least two completed inspections before publishing an average. A count like "oops" is invalid input. A count of 1 is valid input that falls below the site’s minimum. Give the caller a different error for each case.

class InspectionMinimumError(Exception):
    pass


def average_score(total_score, raw_count):
    try:
        count = int(raw_count)
    except ValueError as error:
        # Keep the original conversion error available for debugging.
        raise ValueError("Enter a whole inspection count.") from error

    if count < 0:
        raise ValueError("Inspection count cannot be negative.")
    if count < 2:
        raise InspectionMinimumError("At least two inspections are required.")

    return total_score / count


for raw_count in ["oops", "1", "2"]:
    try:
        average = average_score(170, raw_count)
    except (ValueError, InspectionMinimumError) as error:
        print(error)
    else:
        print(f"Average: {average:.1f}")

Expected output

Enter a whole inspection count.
At least two inspections are required.
Average: 85.0

raise stops the current call and sends the exception to a handler. raise ... from error preserves the cause in a traceback. The else block reports success only if the call completes without an exception. An unexpected programming error can still reach the caller.

Predict what happens with zero and negative counts

"0" raises InspectionMinimumError before any division. "-1" raises ValueError because a negative count is invalid.

1.5.2 pathlib and context managers

Save a receipt and read it back. Path describes the location and open gives you a file handle. The example uses a temporary folder and cleans it up afterward.

Run the code

from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    path = Path(folder) / "receipt.txt"
    with path.open("w", encoding="utf-8") as handle:
        handle.write("Penny: EUR 12")
    with path.open(encoding="utf-8") as handle:
        receipt = handle.read()
    print(receipt)

Output

Penny: EUR 12

How it works

  1. Path(folder) / filename builds the path for the current operating system.
  2. Mode "w" opens the file for writing. The first with block closes the handle after write().
  3. The second with block uses the default read mode. read() returns the text stored in receipt.
Common mistake

Mode "w" truncates an existing file. The handle gives access to the file. Relative paths are resolved from the current working directory.

The with block closes the file automatically. To update a report, you can write a temporary file in the same directory and replace the original. Atomic replacement alone does not guarantee backups or durability after power loss.

Try a change

Where does report.txt go if you replace receipt.txt with that name? Why specify the encoding?

Check your reasoning

The new name goes in the same temporary folder. UTF-8 helps machines interpret the same text consistently.

Inspect a project folder with os and pathlib

A relative path starts from the current working directory. An absolute path identifies a location from the filesystem root. If your file can’t be found, print the working directory first. Running a script from a different folder can change that directory.

import os
from pathlib import Path
from tempfile import TemporaryDirectory

# Use an isolated folder so the same example works on any machine.
with TemporaryDirectory() as folder:
    report = os.path.join(folder, "report.txt")
    Path(report).write_text("ready", encoding="utf-8")

    print(sorted(os.listdir(folder)))
    print(Path(report).is_absolute())
    print((Path(folder) / "report.txt").read_text(encoding="utf-8"))

Expected output

['report.txt']
True
ready

For your own project, run print(os.getcwd()) or print(Path.cwd()) to see the current folder. Both os.path.join(folder, "report.txt") and Path(folder) / "report.txt" build a path with the right separator for your system. Missing files can raise FileNotFoundError. The exception section shows how to handle it.

Read, rewind and append to an inspection file

A file has a current read position. After read() reaches the end, another read() returns an empty string. Use seek(0) to go back to the start. Run this example in a temporary folder so your own report files stay safe.

from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    path = Path(folder) / "inspection.txt"

    with path.open("x", encoding="utf-8") as report:
        report.write("Status: open\n")

    with path.open("a", encoding="utf-8") as report:
        report.write("Review: pending\n")

    with path.open("r", encoding="utf-8") as report:
        print(report.readline().strip())
        saved_position = report.tell()
        print(report.read().strip())
        print("At end:", repr(report.read()))
        report.seek(saved_position)
        print("Read again:", report.readline().strip())
        report.seek(0)
        print("From start:", report.readline().strip())

Expected output

Status: open
Review: pending
At end: ''
Read again: Review: pending
From start: Status: open

x creates a new file and raises FileExistsError if it already exists. a appends, r reads and w clears an existing file when it opens it for writing. Each with closes the file when its block ends.

In text mode, treat the result of tell() as a saved position you can give back to seek(). To change a field in a short report, read and edit the text, then write a separate revised file. A character index from find() may differ from the position required by seek().

1.5.3 CSV parsing

A merchant name contains a comma, as in "Shop, Berlin". Splitting on commas would break the field. DictReader creates one dictionary per row using the headers. StringIO lets us use text as a file-like stream.

Run the code

import csv
from io import StringIO

source = StringIO('id,merchant,amount\nT1,"Shop, Berlin",12\n')
reader = csv.DictReader(source)
for row in reader:
    print(row["merchant"])
    print(type(row["amount"]).__name__)
    print(int(row["amount"]) + 1)

Output

Shop, Berlin
str
13

How it works

  1. The headers supply the id, merchant and amount keys.
  2. The parser keeps the quoted comma inside the merchant field.
  3. The CSV amount starts as the text "12". type(...).__name__ gives the type’s readable name. After int() converts the value, it can be added to the total.
Common mistake

Validate each field after parsing. A missing header, an empty amount and an invalid number are distinct failures. If you skip a row, record its number and a reason that avoids sensitive data.

To open a real file, use path.open(encoding="utf-8", newline="") so the csv module can handle line endings. Set appropriate input and field limits when you accept untrusted data.

Check your reasoning

1.5.4 JSON serialization

To send the report to another service, encode the dictionary as JSON text. dumps produces a string, while dump writes to a file-like object.

Run the code

import json

report = {"currency": "EUR", "spent_cents": 1975, "valid": True}
text = json.dumps(report, sort_keys=True)
print(text)
restored = json.loads(text)
print(restored["spent_cents"])

Output

{"currency": "EUR", "spent_cents": 1975, "valid": true}
1975

How it works

  1. dumps creates a string from the dictionary. JSON writes true in lowercase.
  2. sort_keys gives a predictable display order. The report’s meaning is independent of key order.
  3. loads turns the JSON string back into a dictionary so you can read spent_cents by key.
Common mistake

JSON text and Python dictionaries have different types. Use a JSON parser for untrusted text. The default encoder needs an explicit representation for values such as Decimal or datetime.

Send money as integer cents or a decimal string. Validate allowed fields, types and sizes. Use allow_nan=False when the encoder should reject non-finite floats.

Try a change

Encode and decode a string value of "1975" for spent_cents. What type will you get back?

Check your reasoning

It remains a string. Validate and convert it according to the contract before doing arithmetic.

1.5.5 Decimal for money

EUR 12.50 equals 1,250 cents. Use Decimal with a string input for exact decimal amounts. This exercise accepts finite, positive values in whole cents.

Run the code

from decimal import Decimal

amount = Decimal("12.50")
fee = Decimal("0.25")
net = amount - fee
print(net)
print(int(amount * 100))

Output

12.25
1250

How it works

  1. Decimal receives the string "12.50" directly.
  2. Subtracting the two Decimal values produces 12.25.
  3. Multiplying by 100 produces 1250.00 cents. It is already a whole cent amount, so int conversion is safe.
Common mistake

int(Decimal("1.001") * 100) silently truncates the fractional cent. Validate the whole-cent rule and reject NaN or Infinity before converting.

The project checks input length and range, finiteness, sign and fractional cents. Formatting to two places affects display only. Follow the business rounding rule when amounts require rounding.

Try a change

Compare Decimal(0.1) with Decimal("0.1"). Why can they differ?

Check your reasoning

The literal 0.1 first becomes a binary float. Decimal then represents that approximation. The string form represents the intended decimal directly.

Where to start debugging

If the file is missing, check Path.cwd() and the resolved path. If the CSV total is wrong, inspect the headers, quoting, empty fields and conversions. Keep full customer records, passwords and tokens out of error logs.

Practice 1: CSV Import with Rejections

Require a positive integer amount_cents in the CSV. Total the valid rows and record the numbers of rejected rows.

Hint

Use enumerate with start=2 because the header is row 1.

See Solution

Validate each row independently so processing can continue after an invalid one.

Walk through the solution

The try block checks conversion and positivity for each row. The handler records the bad row number and continues. The accepted rows total 1975.

import csv
from io import StringIO
source = StringIO('id,amount_cents\nT1,1250\nT2,oops\nT3,-2\nT4,725\n')
total = 0
rejected = []
for line, row in enumerate(csv.DictReader(source), start=2):
    try:
        amount = int(row['amount_cents'])
        if amount <= 0:
            raise ValueError('Nonpositive amount')
    except (ValueError, TypeError):
        rejected.append(line)
        continue
    total += amount
print('Check:', total == 1975)
print('Check:', rejected == [3, 4])

Output

Check: True
Check: True

Check your work

An invalid header affects the whole batch. An invalid amount affects its row. Add a check that rejects a missing amount_cents header.

Practice 2: Safe Money to JSON

Convert a positive euro amount string to integer cents. Reject NaN, Infinity, blanks, negatives and fractional cents. Then encode the result as JSON.

Hint

Check that the Decimal is finite before comparing it and avoid converting through float. Limit input to 30 characters for this exercise.

See Solution

Limit the input, parse it, check finiteness and range, validate whole cents and convert to an integer.

Walk through the solution

Decimal takes a string. After the finite and range checks, the code verifies that the amount contains whole cents before calling int.

import json
from decimal import Decimal, InvalidOperation

def to_cents(raw):
    text = raw.strip()
    if not text or len(text) > 30:
        raise ValueError('Invalid input length')
    try:
        value = Decimal(text)
    except InvalidOperation as error:
        raise ValueError('Invalid amount') from error
    if not value.is_finite() or not 0 < value <= Decimal('1000000'):
        raise ValueError('Amount outside allowed range')
    if value * 100 != (value * 100).to_integral_value():
        raise ValueError('Fractional cents')
    return int(value * 100)
print('Check:', to_cents('12.50') == 1250)
for bad in ('NaN', 'Infinity', '', '-1', '1.001'):
    try:
        to_cents(bad)
    except ValueError:
        pass
    else:
        raise AssertionError(f'Accepted invalid input: {bad}')
print('Check:', json.loads(json.dumps({'amount_cents': to_cents('7.25')}))['amount_cents'] == 725)

Output

Check: True
Check: True

Check your work

The valid amount survives a JSON round trip. Every invalid value raises ValueError.
