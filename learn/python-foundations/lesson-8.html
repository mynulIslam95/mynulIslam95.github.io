1.8 pytest, Debugging & Logging

1.8.1 pytest assertions

Test হলো code দিয়ে লেখা expected behavior। assert actual == expected fail করলে pytest difference দেখায়। Test file-এর নাম test_*.py, function-এর নাম test_* রাখো। নিচের code test_fees.py হিসেবে save করো, তারপর python -m pytest -q run করো। Production input validation-এর জন্য assert ব্যবহার করবে না; optimized Python mode-এ assertions disable হতে পারে।

def calculate_fee(amount_cents):
    if amount_cents < 0:
        raise ValueError("Negative amount")
    return amount_cents * 250 // 10000

def test_fee_for_one_hundred_euros():
    assert calculate_fee(10000) == 250

def test_zero_fee():
    assert calculate_fee(0) == 0

1.8.2 Arrange Act Assert

Arrange-এ setup, Act-এ যে behavior test করছি সেটা call, Assert-এ expected outcome। নাম থেকে failure বোঝা উচিত। test_1-এর বদলে test_rejected_debit_keeps_balance useful। Result test করো, implementation-এর প্রতিটি internal line mirror করে brittle test বানাবে না। Database বা external service লাগলে পরে integration test আলাদা হবে।

def debit(balance, amount):
    if amount <= 0 or amount > balance:
        raise ValueError("Debit rejected")
    return balance - amount

def test_valid_debit_returns_remaining_balance():
    opening = 10000  # Arrange
    remaining = debit(opening, 2500)  # Act
    assert remaining == 7500  # Assert

1.8.3 Edge cases and parametrization

Happy path-এর পাশে empty input, zero, negative, exact threshold, one over threshold আর malformed type ভাবো। সব possible input enumerate করা লাগবে না, meaningful partitions বেছে নাও। pytest.mark.parametrize একই behavior কয়েক input-এ test করে। Expected exception-এর জন্য pytest.raises ব্যবহার করো। Broad Exception catch করলে wrong error-ও pass করতে পারে।

import pytest

def review(amount):
    if amount < 0:
        raise ValueError("Negative amount")
    return amount > 8000

@pytest.mark.parametrize("amount, expected", [(0, False), (8000, False), (8001, True)])
def test_review_boundary(amount, expected):
    assert review(amount) is expected

def test_negative_amount_is_rejected():
    with pytest.raises(ValueError, match="Negative"):
        review(-1)

1.8.4 Tracebacks

Traceback-এর শেষ line exception type ও message দেখায়। তার উপরের frames কোন calls থেকে এসেছ সেটা বলে। “যেই line crash করেছে” আর “যেখানে wrong value তৈরি হয়েছে” একই নাও হতে পারে। Small reproduction বানাও, সন্দেহের boundary-তে value ও type inspect করো। breakpoint() দিয়ে debugger-এ pause করে p variable, n next আর c continue ব্যবহার করতে পারো। Shared/production output-এ sensitive data inspect বা print করবে না।

raw = "1250"
# print(10000 - raw) would raise TypeError: raw is text.
amount_cents = int(raw)
remaining = 10000 - amount_cents
assert remaining == 8750
# For local investigation, put breakpoint() before the calculation.

1.8.5 Logging without secrets

Log event, request ID আর safe status রাখবে, full token/password/customer payload না। logging.getLogger(__name__) module logger দেয়। Library function বারবার basicConfig করবে না; application entry point configure করবে। Exception catch করে re-raise করার আগে প্রতিটি layer-এ একই traceback log করলে noise হয়। Useful boundary-তে একবার log করো। Logging আর user-friendly error response আলাদা।

import logging

logger = logging.getLogger("tracker")
logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s")
request_id = "demo-42"
rejected_rows = 2
logger.info("import_complete request_id=%s rejected_rows=%s", request_id, rejected_rows)
assert rejected_rows == 2

Debugging: কোথা থেকে শুরু করবে?

Fix করার আগে failing test দেখাও। তারপর smallest change দিয়ে pass করো। Test pass হলে bug-এর nearby boundary check করো। Slow বা flaky test ঠিক করতে arbitrary sleep যোগ না করে shared state, timing dependency আর cleanup দেখো।

Practice 1: Catch the Threshold Bug

এক developer amount >= 8000 লিখেছে। Requirement > 8000। Regression test দিয়ে bug ধরো, তারপর fix করো।

Hint

Exact boundary 8000 ছাড়া শুধু 9000 test করলে bug ধরা পড়বে না।

See Solution

দুই adjacent values 8000 ও 8001 test করো।

def requires_review(amount_cents):
    return amount_cents > 8000

def test_exact_threshold_is_not_reviewed():
    assert requires_review(8000) is False

def test_one_cent_over_threshold_is_reviewed():
    assert requires_review(8001) is True

test_exact_threshold_is_not_reviewed()
test_one_cent_over_threshold_is_reviewed()

নিজের কাজ মিলিয়ে দেখো

Temporarily >= বসালে প্রথম test fail করবে। ঠিক করার পরে দুই test pass করবে।

Practice 2: Assert an Invalid-input Contract

parse_amount("oops") ValueError দেবে, valid integer string int return করবে। pytest দিয়ে test করো।

Hint

Invalid input-এ 0 return করলে caller malformed আর genuine zero আলাদা করতে পারবে না।

See Solution

Contract-এ exception explicit রাখো; pytest.raises exact category verify করবে।

import pytest

def parse_amount(raw):
    return int(raw)

def test_valid_integer():
    assert parse_amount("1250") == 1250

def test_malformed_amount():
    with pytest.raises(ValueError):
        parse_amount("oops")
