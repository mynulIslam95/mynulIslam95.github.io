1.8 pytest, Debugging & Logging

Refund function সাধারণ input-এ কাজ করছে, কিন্তু zero amount-এ wrong result। User report দিয়েছে, “কখনো balance ভুল হয়”। এখন guess না করে bug reproduce, expected result define আর regression test দিয়ে fix verify করবো।

1.8.1 pytest assertions

এতদিন output দেখে result মিলিয়েছি। বারবার একই result যাচাই করতে test লিখবো। assert-এর condition false হলে AssertionError হয়। Pytest সেটা test failure হিসেবে report করে। আগে plain Python-এ assert-এর behavior দেখি।

Code-টা run করি

def remaining(balance, expense):
    return balance - expense

actual = remaining(100, 12)
assert actual == 88
print("Check passed")

Output

Check passed

কীভাবে এই result হলো?

  1. Function থেকে actual 88 এসেছে।
  2. 88 == 88 True, তাই assert execution চালিয়ে যেতে দিয়েছে।
  3. Expected 87 লিখলে False হবে, AssertionError-এ শেষ print পর্যন্ত পৌঁছাবে না।
এখানে যেটা ভুল হতে পারে

Production input validation-এর জন্য assert ব্যবহার করবে না। Optimized Python-এ assertions disable হতে পারে। User input invalid হলে explicit validation/exception ব্যবহার করো।

প্রথম test run করতে Lesson 1.7-এর venv-এ pytest install করো। Expected result নিজে business rule থেকে লেখো; implementation copy করে expected হিসাব করলে একই bug test-এও থাকতে পারে।

এবার তুমি বদলে দেখো

এই code test file-এ নিতে কী বদলাবে?

Reasoning মিলিয়ে দেখো

def test_remaining_balance(): নামে function-এর ভিতরে assert remaining(100, 12) == 88 রাখো। File test_balance.py হলে python -m pytest -q collect/run করবে।

1.8.2 Arrange Act Assert

Arrange হলো input/setup, Act হলো target operation, Assert হলো expected behavior। তিনটা stage পরিষ্কার রাখলে failure-এর meaning বোঝা যায়। একই কাজ repeated setup-এ জটিল করে ফেলবো না।

Code-টা run করি

def debit(balance, amount):
    return balance - amount

def test_valid_debit():
    opening = 100
    remaining = debit(opening, 12)
    assert remaining == 88

test_valid_debit()
print("Test passed")

Output

Test passed

কীভাবে এই result হলো?

  1. opening = 100 test input arrange করছে।
  2. debit(opening, 12) operation under test।
  3. Assert expected outcome check করে। নিচে direct call শুধু এই standalone example run করার জন্য।
এখানে যেটা ভুল হতে পারে

শুধু “function called হয়েছে” test করলে result wrong হলেও pass হতে পারে। Implementation-এর every internal call mirror করলে harmless refactor-এ tests ভাঙতে পারে।

pytest দিয়ে collect করালে test_valid_debit নিজে call করতে হবে না। Database interaction-এর correctness later integration test-এ দেখবে; pure rule-এর test দ্রুত ও isolated রাখা যায়।

এবার তুমি বদলে দেখো

debit-এর ভিতরে ভুল করে balance + amount লিখলে test কোথায় fail করবে?

Reasoning মিলিয়ে দেখো

remaining 112 হবে। Assert line fail করবে, কারণ expected 88। Test failure location সবসময় root-cause location না।

1.8.3 Edge cases and parametrization

“Above €80” rule-এ 80 exact boundary, 81 just above। শুধু 100 test করলে >= বনাম > bug ধরা পড়ে না। Cases table-এ expected behavior আগে লিখি।

Code-টা run করি

def needs_review(amount):
    if amount < 0:
        raise ValueError("Negative amount")
    return amount > 80

cases = [(0, False), (80, False), (81, True)]
for amount, expected in cases:
    assert needs_review(amount) is expected
print("3 boundaries passed")

Output

3 boundaries passed

কীভাবে এই result হলো?

  1. তিন input business behavior-এর আলাদা partitions cover করছে।
  2. Tuple unpacking প্রতিটি amount ও expected আলাদা করছে।
  3. যেকোনো wrong output assert fail করবে; সব ঠিক হলে summary print হবে।
এখানে যেটা ভুল হতে পারে

Invalid negative input-এ false return করাই intended কি exception, সেটা contract নির্ধারণ করবে। Exception test-এ broad Exception catch করলে wrong category-ও pass হতে পারে।

নীচের practice-এ parametrized tests-এর runnable version আছে। Empty input, malformed input, exact boundary আর adjacent value থেকে meaningful set বেছে নাও; সব possible numbers enumerate করা লাগবে না।

এবার তুমি বদলে দেখো

Pytest-এ একই cases কীভাবে আলাদা test results পাবে?

Reasoning মিলিয়ে দেখো

@pytest.mark.parametrize("amount, expected", cases) দিয়ে test_review(amount, expected) লিখলে তিন case আলাদাভাবে run হবে। ValueError-এর জন্য with pytest.raises(ValueError): ব্যবহার করো।

1.8.4 Tracebacks

User বলছে remaining balance wrong। আগে minimal input-এ reproduce করি। Text amount-কে number না ভেবে arithmetic করলে TypeError হতে পারে। Traceback-এর শেষ line error type বলে; উপরের frames call path দেখায়।

Code-টা run করি

raw = "12"
print(type(raw).__name__)
amount = int(raw)
remaining = 100 - amount
print(remaining)

Output

str
88

কীভাবে এই result হলো?

  1. Raw input-এর type str, তাই original bug-এ 100 - raw invalid ছিল।
  2. int(raw) conversion-এর পরে type integer।
  3. এবার arithmetic expected 88 দেয়। Error যেখানে দেখা গেছে তার আগের boundary-তে wrong type তৈরি হয়েছিল।
এখানে যেটা ভুল হতে পারে

Random casts বসিয়ে error থামালেই fix নয়। Input format allowed কি, invalid text কীভাবে handle হবে সেটা verify করতে হবে।

একটা reliable sequence: reproduce → smallest failing example → hypothesis → inspect evidence → smallest fix → regression test। একসাথে পাঁচটা change করলে কোনটা কাজ করেছে বোঝা কঠিন।

এবার তুমি বদলে দেখো

int(raw)-এর আগে breakpoint() বসিয়ে local run করো। কোন দুই value inspect করবে?

Reasoning মিলিয়ে দেখো

raw ও তার type inspect করো। Debugger-এ p raw, p type(raw), n দিয়ে next, c দিয়ে continue করা যায়। Sensitive production values blindly print করবে না।

1.8.5 Logging without secrets

Import fail করেছে, কিন্তু log-এ শুধু “error”। কোন request, কত row reject আর কোন stage ছিল জানলে diagnosis সহজ হয়। Log-এ শুধু safe context রাখবো।

Code-টা run করি

import logging
import sys

logging.basicConfig(level=logging.INFO, stream=sys.stdout, format="%(levelname)s %(message)s", force=True)
logger = logging.getLogger("tracker")
logger.info("import_complete request_id=%s rejected=%s", "demo-42", 2)

Output

INFO import_complete request_id=demo-42 rejected=2

কীভাবে এই result হলো?

  1. Application entry point logging configure করেছে।
  2. Named logger reusable component-এর events identify করতে পারে।
  3. Placeholders দিয়ে safe request ID ও count বসেছে। Token বা full customer payload log হয়নি।
এখানে যেটা ভুল হতে পারে

print(password), full JWT বা entire customer row log করা debugging-এর shortcut হতে পারে না। একই exception প্রতিটি layer-এ log করলে duplicate noise হয়।

INFO normal significant event, WARNING recoverable concern, ERROR failed operation-এর জন্য useful levels। Log message user-facing error response-এর replacement না। Library function-এ বারবার global config করবে না।

এবার তুমি বদলে দেখো

এক import-এর সব events connect করতে কী field রাখবে? Request ID-ই authorization proof কি?

Reasoning মিলিয়ে দেখো

Consistent correlation/request ID দিয়ে events trace করা যায়। কিন্তু সেটা permission proof না; authorization আলাদা trusted identity/policy দিয়ে হবে।

Debugging: কোথা থেকে শুরু করবে?

Fix করার আগে failing test দেখাও। তারপর smallest change দিয়ে pass করো। Test pass হলে bug-এর nearby boundary check করো। Slow বা flaky test ঠিক করতে arbitrary sleep যোগ না করে shared state, timing dependency আর cleanup দেখো।

Practice 1: Catch the Threshold Bug

এক developer amount >= 8000 লিখেছে। Requirement > 8000। Regression test দিয়ে bug ধরো, তারপর fix করো।

Hint

Exact boundary 8000 ছাড়া শুধু 9000 test করলে bug ধরা পড়বে না।

See Solution

দুই adjacent values 8000 ও 8001 test করো।

Solution-টা বুঝে নিই

Exact boundary case ভুল >= implementation ধরবে। One-over case valid positive path ধরে। দুইটা test একে অপরের duplicate না।

def requires_review(amount_cents):
    return amount_cents > 8000

def test_exact_threshold_is_not_reviewed():
    assert requires_review(8000) is False

def test_one_cent_over_threshold_is_reviewed():
    assert requires_review(8001) is True

test_exact_threshold_is_not_reviewed()
test_one_cent_over_threshold_is_reviewed()

এই solution test functions define করে। নিচের command দিয়ে pytest-এ run করো।

নিজের কাজ মিলিয়ে দেখো

Temporarily >= বসালে প্রথম test fail করবে। ঠিক করার পরে দুই test pass করবে।

Practice 2: Assert an Invalid-input Contract

parse_amount("oops") ValueError দেবে, valid integer string int return করবে। pytest দিয়ে test করো।

Hint

Invalid input-এ 0 return করলে caller malformed আর genuine zero আলাদা করতে পারবে না।

See Solution

Contract-এ exception explicit রাখো; pytest.raises exact category verify করবে।

Solution-টা বুঝে নিই

pytest.raises block-এ ValueError না এলে test fail হবে। Valid input-এর আলাদা assertion আছে, তাই function সবসময় exception দিলেও suite pass করবে না।

import pytest

def parse_amount(raw):
    return int(raw)

def test_valid_integer():
    assert parse_amount("1250") == 1250

def test_malformed_amount():
    with pytest.raises(ValueError):
        parse_amount("oops")

এই solution test functions define করে। নিচের command দিয়ে pytest-এ run করো।

নিজের কাজ মিলিয়ে দেখো

test_amounts.py নামে save করে python -m pytest -q run করো। Failure report-এর location explain করতে পারবে।
