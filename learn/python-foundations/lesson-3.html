Functions & scope

In the previous lesson, you checked one payment and then processed a batch. This time, move the decision into a function so the same rule can be reused. You’ll see what goes in, what comes back and which variables the function can change.

Turn one calculation into a function

Create payment_functions.py in your practice folder. Run it from that folder with py -3 payment_functions.py on Windows or python3 payment_functions.py on macOS or Linux. Predict both results before you run it.

def remaining_balance(balance, expense):
    # Return a new balance for the caller to use.
    return balance - expense


remaining = remaining_balance(100, 12)
print(remaining)
print(remaining_balance(expense=8, balance=50))

Expected output

88
42

def defines the function. Python runs the indented body when you call it. balance and expense are parameters, the names in the definition. 100 and 12 are arguments, the values passed by the caller. In the second call, keywords match each value to its parameter by name.

return ends the call and sends a value back. Here the caller saves it as remaining and decides when to print it. Replace return balance - expense with print(balance - expense), then predict the first two lines again.

Check your prediction

The first line is 88 from inside the function. The second is None from print(remaining). Restore the return so the caller can use the number.

See which balance changes

Replace the file with this version. The caller and the function both use the name balance. Predict which line prints 100.

def remaining_balance(balance, expense):
    # This assignment changes the local name inside the function.
    balance = balance - expense
    return balance


balance = 100
updated = remaining_balance(balance, 12)
print(balance)
print(updated)

Expected output

100
88

Inside the function, the parameter balance is a local name. Assigning a new integer to it leaves the caller’s balance at 100. The returned 88 is now in updated. To keep 88 in the caller’s balance, write balance = remaining_balance(balance, 12).

Local scope applies to names. If you pass in a list and the function calls append() on it, the caller can see that change. You’ll explore this further in memory management.

Reuse the payment rules in a loop

Now separate the decision from the report. The function decides the status of one payment. The loop updates the balance and prints the results. Before running this version, predict what happens to the balance after the EUR 120 request.

def payment_status(balance, amount):
    """Return the decision for one payment in whole euros."""
    if amount <= 0:
        return "Invalid amount"
    if amount > balance:
        return "Not enough balance"
    return "Approved"


balance = 100
for amount in [12, 120, 0, 8]:
    # Reuse the decision with the balance for this turn.
    status = payment_status(balance, amount)
    if status == "Approved":
        balance -= amount
    print(f"EUR {amount}: {status}")

print(f"Balance: EUR {balance}")

Expected output

EUR 12: Approved
EUR 120: Not enough balance
EUR 0: Invalid amount
EUR 8: Approved
Balance: EUR 80

After EUR 12 is paid, the next call gets a balance of EUR 88. The EUR 120 request returns early with Not enough balance. The caller only subtracts approved amounts, so EUR 88 is still available for the next request. The docstring under def describes what the function returns and the unit it expects.

Choose a default the caller can override

A customer kickoff usually takes five minutes per data source. Put the usual value in the definition. Try both calls so you can see when Python uses the default.

def estimated_minutes(source_count, minutes_per_source=5):
    # The caller can override the usual five minutes per source.
    return source_count * minutes_per_source


print(estimated_minutes(3))
print(estimated_minutes(3, minutes_per_source=2))

Expected output

15
6

The first call passes only the source count, so Python uses 5. The second passes 2 for minutes_per_source. Put required parameters before ones with defaults.

Build a voice clip billing function

In this practice app, each voice clip includes two free minutes. Write billable_minutes(duration, included=2) to return the chargeable minutes for one clip. Assume both values are non-negative whole minutes. Use a loop outside the function to total the results for [1, 5, 2, 8].

  • A clip at or below its allowance returns 0. A longer clip returns the difference.
  • The batch should print Billable minutes: 9. An empty batch should print Billable minutes: 0.
  • Call the function with duration=5 and included=3. The caller should print With 3 included: 2.
Reveal the commented solution 
def billable_minutes(duration, included=2):
    """Return the minutes to charge for one voice clip."""
    # Charge zero when the clip fits in the included time.
    if duration <= included:
        return 0
    return duration - included


total = 0
for duration in [1, 5, 2, 8]:
    total += billable_minutes(duration)
print(f"Billable minutes: {total}")
print(f"With 3 included: {billable_minutes(5, included=3)}")

Expected output

Billable minutes: 9
With 3 included: 2

Before moving on, explain where the total lives and why a clip exactly at the allowance returns zero.

Eight tricky interview questions
In def charge(minutes): and charge(5), which is the parameter?

minutes is the parameter. 5 is the argument passed to it.

What does print() inside a function give back to its caller?

Printing writes to the screen. If the function reaches its end without a return, the caller gets None.

What happens to code after an executed return?

The current call ends immediately. Python resumes at the caller.

Does reassigning an integer parameter update the caller’s variable?

The function changes its local name. The caller updates its own variable by assigning the returned value.

Can a function change a list passed in by the caller?

Yes. Calling append() on that list changes the shared object. Make a copy first when you need to preserve the original.

When does Python create the list in def record(event, history=[]):?

Python creates it when it evaluates the definition. Later calls that omit history reuse it.

Can you call estimated_minutes(3, source_count=4)?

Python raises TypeError. The positional and keyword arguments both fill source_count.

What does the if __name__ == "__main__": guard protect?

It runs its body when the file is executed directly. Code outside the guard can still run during import.

Give each call its own list

A default list such as tags=[] is created once when Python defines the function. If the function appends to it, later calls can inherit previous tags. Use None as the default and make a new list inside the function. Copy an existing list before adding a tag if it should stay intact.

def add_tag(tag, tags=None):
    # Give this call its own list before adding the tag.
    result = [] if tags is None else tags.copy()
    result.append(tag)
    return result


original = ["open"]
print(add_tag("review", original))
print(original)
print(add_tag("urgent"))

Expected output

['open', 'review']
['open']
['urgent']
