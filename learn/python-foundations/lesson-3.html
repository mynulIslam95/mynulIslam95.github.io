1.3 Functions, Scope & Modules

একই balance calculation বারবার copy করতে হচ্ছে। এবার একটা reusable function বানাবো। তুমি input দেবে, function result ফেরত দেবে। তারপর scope, defaults আর imports-এর tricky parts দেখবো।

এই Lesson শেষে: Reusable functions লিখতে, mutable default bug এড়াতে আর script-কে modules-এ ভাগ করতে পারবে।

1.3.1 Parameters and returns

একই balance calculation তিন জায়গায় copy হয়েছে। Function-এ rule রাখলে caller input দেয় আর result নেয়। প্রথমে সাধারণ function, তারপর validation। এখানে def function define করে; body call করার সময় execute হয়।

Code-টা run করি

def remaining_balance(balance, expense):
    result = balance - expense
    return result

remaining = remaining_balance(100, 12)
print(remaining)

Output

88

কীভাবে এই result হলো?

  1. Definition পড়ে Python function তৈরি করে, body তখনো চালায় না।
  2. Call-এর 100 ও 12 function-এর balance ও expense parameters-এ যায়।
  3. return 88 caller-কে দেয়। Caller সেটা remaining-এ রেখে print করে।
এখানে যেটা ভুল হতে পারে

ভেতরে শুধু print(result) লিখলে screen-এ দেখা যাবে, কিন্তু function default None return করবে। Return-এর পরে একই call-এর body আর execute হয় না।

Amount-এর unit নামের মধ্যে রাখো যখন cents ব্যবহার করবে। Function parameter হচ্ছে definition-এর নাম; argument হচ্ছে call-এর actual input। Keyword দিয়ে remaining_balance(expense=12, balance=100)-ও call করা যায়।

এবার তুমি বদলে দেখো

Function-এর return result-এর বদলে print(result) দাও। বাইরের print(remaining) কী দেখাবে?

Reasoning মিলিয়ে দেখো

ভেতরের print 88 দেখাবে, বাইরের print None দেখাবে। Display করা আর caller-কে data দেওয়া আলাদা।

1.3.2 Default arguments

অনেক calls-এ একই fee লাগলে default parameter useful। কিন্তু mutable default-এর lifetime বুঝতে হবে। এখানে None দিয়ে “কোনো tags দেওয়া হয়নি” represent করছি।

Code-টা run করি

def add_tag(tag, tags=None):
    if tags is None:
        result = []
    else:
        result = tags.copy()
    result.append(tag)
    return result

print(add_tag("billing"))
print(add_tag("urgent"))

Output

['billing']
['urgent']

কীভাবে এই result হলো?

  1. Caller tags দেয়নি, তাই default None।
  2. প্রতিবার function body-তে নতুন result list বানানো হচ্ছে।
  3. দ্বিতীয় call আগের billing list reuse করছে না।
এখানে যেটা ভুল হতে পারে

def add_tag(tag, tags=[])-এর default list definition-এর সময় একবার তৈরি হয়। সেটা mutate করলে consecutive calls data share করবে।

সাধারণ numeric default যেমন fee=2 mutable-list problem তৈরি করে না। Default থাকলেও caller explicit value দিয়ে override করতে পারে।

এবার তুমি বদলে দেখো

original = ["open"] দিয়ে add_tag("review", original) call করো। original বদলাবে কি?

Reasoning মিলিয়ে দেখো

এই implementation passed list copy করে। Returned list open/review, original শুধু open থাকবে।

1.3.3 Scope and pure functions

Calculation function-এর বাইরের balance বদলাবে, নাকি নতুন value ফেরত দেবে? Contract আগে ঠিক করি। এখানে pure calculation রাখবো: input থেকে result, বাইরের state edit নয়।

Code-টা run করি

balance = 100
def after_expense(current, amount):
    current = current - amount
    return current

updated = after_expense(balance, 12)
print(balance)
print(updated)

Output

100
88

কীভাবে এই result হলো?

  1. Function-এর current local name call-এর value refer করছে।
  2. Local reassignment বাইরের balance নামকে reassign করে না।
  3. Caller নতুন result updated-এ রেখেছে, তাই original balance 100।
এখানে যেটা ভুল হতে পারে

Global variable silently বদলালে call order ও tests একে অপরকে affect করতে পারে। Mutable object pass করলে ভিতরে mutate করা সম্ভব; local name হওয়া deep copy নয়।

Scope lookup সাধারণভাবে local, enclosing function, module global, তারপর built-ins-এর দিকে যায়। এই stage-এ global/nonlocal দিয়ে business state ছড়ানোর বদলে explicit input ও return রাখো।

এবার তুমি বদলে দেখো

ব্যবহার শেষে balance-ই update করতে চাইলে caller কী লিখবে?

Reasoning মিলিয়ে দেখো

balance = after_expense(balance, 12)। Side effect লুকানো নয়, assignment caller-এর কাছে visible।

1.3.4 Imports and modules

Module হলো একটা Python file। Function import করে reuse করতে চাই, কিন্তু import করলেই CLI prompt শুরু হোক সেটা চাই না। নিচের file report.py নামে save করো।

Code-টা run করি

def total_expenses(amounts):
    return sum(amounts)

def main():
    print(total_expenses([12, 8]))

if __name__ == "__main__":
    main()

Output

20

কীভাবে এই result হলো?

  1. python report.py দিয়ে run করলে special name __name__ হয় __main__, তাই main call হয়।
  2. অন্য file থেকে import report করলে __name__ হয় report; guard-এর condition false।
  3. তখন report.total_expenses([12, 8]) call করা যাবে, কিন্তু CLI print automatically হবে না।
এখানে যেটা ভুল হতে পারে

Import top-level statements execute করতে পারে। Guard ছাড়া input(), file write বা network call থাকলে import-এ unexpected work হবে। নিজের file json.py রাখলে standard library shadow করতে পারে।

ছোট project-এ fees.py calculation, io_helpers.py file handling আর main.py CLI entry point হতে পারে। প্রতিটি ছোট expression-এর জন্য আলাদা file বানানো প্রয়োজন নেই।

এবার তুমি বদলে দেখো

একই folder-এ অন্য file থেকে from report import total_expenses করো। Import নিজে 20 print করবে কি?

Reasoning মিলিয়ে দেখো

না, এই guard থাকার কারণে print হবে শুধু explicitly function call করলে। পরে print(total_expenses([5, 6])) দিলে 11।

1.3.5 Docstrings and decomposition

একটা function raw input parse, fee calculate, file save ও receipt print সব করলে failure-এর জায়গা খুঁজে পাওয়া কঠিন। Small responsibility বেছে readable নাম ও contract লিখি।

Code-টা run করি

def total_positive_expenses(amounts):
    """Return the total of positive whole-euro expenses."""
    total = 0
    for amount in amounts:
        if amount > 0:
            total += amount
    return total

print(total_positive_expenses([12, -5, 8]))

Output

20

কীভাবে এই result হলো?

  1. Docstring function-এর input unit ও selection rule বলছে।
  2. Loop-এ -5 বাদ যায়। 12 ও 8 total হয়।
  3. Return value নিয়ে caller display, save বা আরও calculation করতে পারে।
এখানে যেটা ভুল হতে পারে

Docstring-এ code-এর প্রতিটি line repeat করার দরকার নেই। Unit, surprising rule আর invalid-input behavior বেশি useful। Naming সুন্দর হলেও wrong business rule tests ছাড়া ধরা নাও পড়তে পারে।

এবার তুমি বদলে দেখো

Zero include করলে এই total বদলাবে কি? Count-ও return করলে কী difference হবে?

Reasoning মিলিয়ে দেখো

Zero যোগ করলে total বদলায় না। কিন্তু accepted expense count রাখলে zero valid কি না policy গুরুত্বপূর্ণ। Output contract অনুযায়ী test বদলাবে।

Debugging: কোথা থেকে শুরু করবে?

Caller None পাচ্ছে? Function-এ return আছে কি না দেখো। Calls-এর মধ্যে আগের values থাকছে? Mutable default আছে কি না দেখো। Import-এর সময় CLI শুরু হচ্ছে? Entry-point guard check করো।

Practice 1: একই Calculation Reuse করো

remaining(balance, expense) function লিখো। (100,12) আর (50,8) input-এ result return করবে। Function-এর মধ্যে print করবে না।

Hint

আগের example-এর return pattern follow করো।

See Solution

Caller result display করবে, function calculation own করবে।

Solution-টা বুঝে নিই

Function-এর ভিতরের return result caller-কে দেয়। দুই call আলাদা inputs পেয়েছে, তাই result 88 ও 42। ভেতরে print থাকলে বাইরে reuse করার value পাওয়া যেত না।

def remaining(balance, expense):
    return balance - expense
print(remaining(100, 12))
print(remaining(50, 8))

Output

88
42

নিজের কাজ মিলিয়ে দেখো

Output 88 ও 42। print ব্যবহার করে return বাদ দিলে caller কেন None পায় explain করো।

Practice 2: Request History মিশবে না

append_event(event, history=None) লিখো। নতুন result list return করবে; passed history change করবে না।

Hint

None হলে fresh list, অন্যথায় copy।

See Solution

State function-এর বাইরে লুকিয়ে রাখার দরকার নেই।

Solution-টা বুঝে নিই

None হলে fresh result, history থাকলে copy। Caller-এর old list edit না করে returned result-এ নতুন event append হয়েছে।

def append_event(event, history=None):
    result = [] if history is None else history.copy()
    result.append(event)
    return result
old = ['received']
print(append_event('validated', old))
print(old)
print(append_event('new'))

Output

['received', 'validated']
['received']
['new']

নিজের কাজ মিলিয়ে দেখো

প্রথম result received/validated, old শুধু received, শেষ result শুধু new।
