Operators & conditions

You’re building a payment check for a customer. They have EUR 100. Try EUR 20 first. How much will be left? Then try a payment of exactly EUR 100. Should it go through?

1. Start with a calculation and a question

In your practice folder, create payment_check.py. Save the code below. From that folder, run py -3 payment_check.py on Windows or python3 payment_check.py on Mac or Linux.

balance = 100
amount = 20

# Calculate a new value and check whether the payment uses the full balance.
print(f"Left after payment: EUR {balance - amount}")
print(f"Uses the full balance: {amount == balance}")

Expected output

Left after payment: EUR 80
Uses the full balance: False

The minus sign calculates a new value. The double equals asks whether two values are equal. Change amount to 100, save and run again. You should see EUR 0 and True.

2. Choose which code runs

Replace the file contents with the code below. Before running it, read down the checks. if starts the decision. elif means “otherwise, try this check.” else runs when the earlier checks are false. End each branch header with a colon and use four spaces for the lines inside it.

balance = 100
amount = 100

# Reject invalid amounts before checking what the customer can afford.
if amount <= 0:
    print("Amount must be positive")
elif amount > balance:
    print("Not enough balance")
else:
    balance = balance - amount
    print(f"Payment approved. Balance: EUR {balance}")

Expected output

Payment approved. Balance: EUR 0

Watch why the exact balance works. 100 <= 0 is false, and so is 100 > 100. Python reaches else and subtracts EUR 100. Try 120, 0 and -1 one at a time. Predict the message before each run.

Check your predictions
  • 120 prints Not enough balance.
  • 0 and -1 print Amount must be positive.

3. Combine rules

With a balance of 100, amount > 0 and amount <= balance allows 20 and 100. Add or when either of two reasons is enough, like a low battery or battery saver pausing a model. Use not to ask whether a flag is off. The project drills put each rule to work.

Eight tricky questions
Which is true when the payment and balance are both 100, amount < balance or amount <= balance?

Only <= is true. Its = includes an exact match.

When should you use = or ==?

Use balance = 100 to assign a value. Use balance == 100 to ask a question. if balance = 100: raises a syntax error.

Why does amount == 10 or 20 pass even if amount is 5?

Python gets False or 20. The number 20 is treated as true in a condition. Write amount == 10 or amount == 20.

What happens when two conditions in one if/elif chain are true?

The first matching branch runs. Two separate if statements can both run.

What does not (False or True) return?

False. Work inside the parentheses first. False or True gives True and not flips it.

Why can runs > 0 and seconds / runs > 10 safely check runs = 0?

The left check is false, so Python skips the right side. This is called short-circuiting. Put the guard before the division.

What does 10 % 3 give and how is it useful at work?

1. Three full batches of three use nine records, leaving one for the final batch.

Why does input() give a different result from the number you typed in your code?

Input 100 arrives as the string "100". "100" == 100 is false. Convert the input before comparing numeric amounts.

Apply the payment rules in a loop

A for loop repeats an action for each item. If you need a set number of turns, for turn in range(3): gives you the values 0, 1 and 2. The report below loops through payment requests instead.

Create payments.py in your practice folder. Save the code and run py -3 payments.py on Windows or python3 payments.py on Mac or Linux.

balance = 100
requests = [" 12 ", "oops", "120", "8", "0"]
spent = 0

for raw in requests:
    text = raw.strip()
    if not (text.isascii() and text.isdigit()):
        print("Enter a whole number")
        continue

    amount = int(text)
    if amount <= 0:
        print("Amount must be positive")
    elif amount > balance:
        print("Not enough balance")
    else:
        balance -= amount
        spent += amount
        print(f"Paid: EUR {amount}")

print(f"Spent: EUR {spent}")
print(f"Balance: EUR {balance}")

Expected output

Paid: EUR 12
Enter a whole number
Not enough balance
Paid: EUR 8
Amount must be positive
Spent: EUR 20
Balance: EUR 80

Trace the loop

  1. for raw in requests takes one item at a time. The square brackets hold a list. The indented lines belong to the loop.
  2. " 12 " becomes "12", then the number 12. It passes both checks, so the else block reduces the balance from EUR 100 to EUR 88. balance -= amount means balance = balance - amount.
  3. "oops" fails the text check. continue skips the rest of this turn. Next, 120 is larger than EUR 88, so that payment is declined.
  4. 8 is approved and leaves EUR 80. 0 fails the positive-amount check. The two unindented print() lines run once after the loop.

if checks the first rule. elif checks the next rule if the first one fails. else runs if both rules fail. Keep the indents consistent, using four spaces per level.

Use for when you have a list of items. Use while when you need to repeat until a condition changes. This example prints 1, 2 and 3.

attempts = 0
while attempts < 3:
    attempts += 1
    print(attempts)

Without attempts += 1, the condition would stay true. break stops the entire loop when you need to exit early.

Check input before converting it

strip() removes spaces at the ends. isascii() and isdigit() together accept digit-only text such as "12". This example rejects blanks, negative amounts and prices with a decimal point. A second check rejects zero.

Common mistake. Keep spent = 0 above the loop. Put it inside and you’ll reset the total on every turn.
