Operators, conditions & loops

Start with one payment. Use operators to calculate the balance and conditions to decide whether it goes through. Then put that decision inside a loop to process a batch.

Operators & conditions

You’re building a payment check for a customer. They have EUR 100. Try EUR 20 first. How much will be left? Then try a payment of exactly EUR 100. Should it go through?

1. Start with a calculation and a question

In your practice folder, create payment_check.py. Save the code below. From that folder, run py -3 payment_check.py on Windows or python3 payment_check.py on Mac or Linux.

balance = 100
amount = 20

# Calculate a new value and check whether the payment uses the full balance.
print(f"Left after payment: EUR {balance - amount}")
print(f"Uses the full balance: {amount == balance}")

Expected output

Left after payment: EUR 80
Uses the full balance: False

The minus sign calculates a new value. The double equals asks whether two values are equal. Change amount to 100, save and run again. You should see EUR 0 and True.

2. Choose which code runs

Replace the file contents with the code below. Before running it, read down the checks. if starts the decision. elif means “otherwise, try this check.” else runs when the earlier checks are false. End each branch header with a colon and use four spaces for the lines inside it.

balance = 100
amount = 100

# Reject invalid amounts before checking what the customer can afford.
if amount <= 0:
    print("Amount must be positive")
elif amount > balance:
    print("Not enough balance")
else:
    balance = balance - amount
    print(f"Payment approved. Balance: EUR {balance}")

Expected output

Payment approved. Balance: EUR 0

Watch why the exact balance works. 100 <= 0 is false, and so is 100 > 100. Python reaches else and subtracts EUR 100. Try 120, 0 and -1 one at a time. Predict the message before each run.

Check your predictions
  • 120 prints Not enough balance.
  • 0 and -1 print Amount must be positive.

3. Combine rules

With a balance of 100, amount > 0 and amount <= balance allows 20 and 100. Add or when either of two reasons is enough, like a low battery or battery saver pausing a model. Use not to ask whether a flag is off. Next, keep the payment rules and repeat them for a batch.

Apply the payment rules in a loop

Now five payment requests arrive. The square brackets hold a list of requests. for raw in requests: picks one request, runs the indented code and repeats for the next request. Each accepted payment changes the balance available for the next turn.

Create payments.py in your practice folder. Save the code and run py -3 payments.py on Windows or python3 payments.py on Mac or Linux.

Before you run it, predict the balance after the first payment and at the end. The requests arrive as text. strip() trims the ends, the digit check protects int() and continue skips the rest of the current turn when a request fails that check.

balance = 100
requests = [" 12 ", "oops", "120", "8", "0"]
spent = 0

for raw in requests:
    # Skip invalid text before converting it to a number.
    text = raw.strip()
    if not (text.isascii() and text.isdigit()):
        print("Enter a whole number")
        continue

    amount = int(text)
    # Apply the same decision to the current balance.
    if amount <= 0:
        print("Amount must be positive")
    elif amount > balance:
        print("Not enough balance")
    else:
        balance -= amount
        spent += amount
        print(f"Paid: EUR {amount}")

# Print the totals once, after every request has been checked.
print(f"Spent: EUR {spent}")
print(f"Balance: EUR {balance}")

Expected output

Paid: EUR 12
Enter a whole number
Not enough balance
Paid: EUR 8
Amount must be positive
Spent: EUR 20
Balance: EUR 80

Use a while loop with a stopping rule

Use for when you have items to process or know how many times to repeat. range(3) gives three turns numbered 0, 1 and 2. Use while when the next turn depends on a condition. In this simulated retry, you can try up to three times. The second attempt succeeds.

attempts = 0
successful_attempt = 2

while attempts < 3:
    # Updating the counter lets the loop reach the limit.
    attempts += 1
    print(f"Attempt {attempts}")
    if attempts == successful_attempt:
        print("Connected")
        break
Attempt 1
Attempt 2
Connected

break exits the loop. continue skips only the current turn. Set successful_attempt to 4 and predict how many attempts are printed.

Check input before converting it

strip() removes spaces at the ends. isascii() and isdigit() together accept digit-only text such as "12". This example rejects blanks, negative amounts and prices with a decimal point. A second check rejects zero.

Common mistake. Keep spent = 0 above the loop. Put it inside and you’ll reset the total on every turn.

Build a batch upload checker

You’re checking requests for the AI Voice Productivity app. Start with 10 minutes available and the requests [0, 4, 8, 6, 1]. Write the program before opening the solution.

  1. Use a for loop to check each request in order.
  2. Print Invalid for zero or negative durations. Print Over quota if the request exceeds the minutes left. Include the duration in either message.
  3. For an approved request, subtract its duration and print Approved with the duration. After the loop, print the minutes left once.
Invalid: 0
Approved: 4
Over quota: 8
Approved: 6
Over quota: 1
Minutes left: 0
Show the commented solution 
minutes_left = 10
requests = [0, 4, 8, 6, 1]

for duration in requests:
    if duration <= 0:
        print(f"Invalid: {duration}")
    elif duration > minutes_left:
        print(f"Over quota: {duration}")
    else:
        # Update the quota only after approving a request.
        minutes_left -= duration
        print(f"Approved: {duration}")

print(f"Minutes left: {minutes_left}")

Run it again with []. You should get only Minutes left: 10. Then explain why rejecting the 8-minute request still lets the next 6-minute request through.

Tricky interview questions
Which is true when the payment and balance are both 100, amount < balance or amount <= balance?

Only <= is true. Its = includes an exact match.

When should you use = or ==?

Use balance = 100 to assign a value. Use balance == 100 to ask a question. if balance = 100: raises a syntax error.

Why does amount == 10 or 20 pass even if amount is 5?

Python gets False or 20. The number 20 is treated as true in a condition. Write amount == 10 or amount == 20.

What happens when two conditions in one if/elif chain are true?

The first matching branch runs. Two separate if statements can both run.

What does not (False or True) return?

False. Work inside the parentheses first. False or True gives True and not flips it.

Why can runs > 0 and seconds / runs > 10 safely check runs = 0?

The left check is false, so Python skips the right side. This is called short-circuiting. Put the guard before the division.

What does 10 % 3 give and how is it useful at work?

1. Three full batches of three use nine records, leaving one for the final batch.

Why does input() give a different result from the number you typed in your code?

Input 100 arrives as the string "100". "100" == 100 is false. Convert the input before comparing numeric amounts.

Why is a running total initialized above a loop?

Each turn needs the total from the previous turn. Setting it to zero inside the loop resets it every time.

When should an invalid request use continue instead of break?

Use continue when you should still check the later requests. break ends the whole loop.

Extra challenge. Check one voice upload

A teammate needs one message per upload. Use a 60-minute budget and 55 minutes already used. Start with a 5-minute request and an active account. A paused account takes priority, then reject zero or negative requests, then reject requests over the remaining quota. For an approved upload, show the minutes left.

  • Exact fit. A 5-minute request prints Upload approved. Minutes remaining: 0.
  • One minute over. A 6-minute request prints Quota exceeded.
  • Invalid duration. A 0-minute or negative request prints Enter a positive duration.
  • Rule priority. Pause the account and request 0 minutes. It should print Account paused.
Reveal the commented solution 
budget_minutes = 60
used_minutes = 55
requested_minutes = 5
account_paused = False

# A paused account takes priority over the other rules.
if account_paused:
    print("Account paused")
elif requested_minutes <= 0:
    print("Enter a positive duration")
elif used_minutes + requested_minutes > budget_minutes:
    print("Quota exceeded")
else:
    remaining_minutes = budget_minutes - used_minutes - requested_minutes
    print(f"Upload approved. Minutes remaining: {remaining_minutes}")
