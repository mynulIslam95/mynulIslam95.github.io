1.7 Type Hints, Clean Code & Dependencies

1.7.1 Annotations and generic types

Type hints tell a caller what a function expects. Start by annotating single values and then the elements of a list.

Run the code

def total_cents(amounts: list[int]) -> int:
    return sum(amounts)

print(total_cents([100, 250]))

Output

350

How it works

  1. amounts: list[int] describes a list of integers.
  2. -> int describes the return value.
  3. The function runs as usual. An annotation alone does not validate the value.
Common mistake

A type checker can warn about a mismatch. Add runtime validation at the boundary where the program accepts data.

Use explicit checks and tests for rules such as positive amounts, matching currencies and tenant access.

Try a change

Will the annotation block a list of strings?

Check your reasoning

The function body runs. sum() raises an error if the values are incompatible.

1.7.2 Dataclasses and Optional

The ticket has no owner yet. Represent that absence with None. str | None allows text or absence. A default of None lets callers omit the argument.

Run the code

from dataclasses import dataclass

@dataclass
class Ticket:
    title: str
    owner: str | None = None

def owner_label(ticket: Ticket) -> str:
    if ticket.owner is None:
        return "unassigned"
    return ticket.owner

print(owner_label(Ticket("Refund")))
print(owner_label(Ticket("Delivery", "Mynul")))

Output

unassigned
Mynul

How it works

  1. The first ticket leaves owner out, so it takes the None default.
  2. The explicit is None check returns unassigned.
  3. The second ticket returns its owner’s name.
Common mistake

A union with None allows that value. Add a default if you also want callers to omit the argument.

Try a change

What does owner_label return for an empty owner string?

Check your reasoning

It returns the empty string because that value is distinct from None. Decide in your validation rules whether a blank owner is allowed.

1.7.3 Naming and refactoring

In calculate(x), the name x hides its unit. Refactor names and boundaries to make the intention clear while preserving behavior.

Run the code

def needs_review(amount_cents: int, threshold_cents: int = 8000) -> bool:
    return amount_cents > threshold_cents

print(needs_review(8000))
print(needs_review(8001))

Output

False
True

How it works

  1. The names tell you that both amounts and the threshold use cents.
  2. The default threshold makes the rule reusable.
  3. The exact boundary and the value one above it show where the rule changes.
Common mistake

Changing > to >= changes the rule. Record baseline cases before refactoring.

Separate calculations, parsing, persistence and formatting where that makes the code easier to follow.

Try a change

What happens with input 9000 and a threshold of 10000?

Check your reasoning

needs_review(9000, threshold_cents=10000) returns False. The explicit argument shows which rule the call uses.

1.7.4 venv and pip

Use a project-specific virtual environment to isolate packages. First, check exactly which interpreter is running.

Run the code

import sys
from pathlib import Path

print(Path(sys.executable).is_absolute())
print("Python", sys.version_info.major)

Output

True
Python 3

How it works

  1. sys.executable reports the path of the current Python interpreter.
  2. True means that the path is absolute.
  3. sys.version_info.major gives the major version. Compare full paths to check whether the editor and terminal use the same environment.
Common mistake

Run python -m pip so installation uses the pip belonging to that particular Python.

Terminal commands: python3 -m venv .venv then on Linux or macOS run source .venv/bin/activate. In Windows PowerShell, run .venv\Scripts\Activate.ps1. You can also run the environment’s interpreter directly. Keep your source outside .venv and exclude the environment from Git.

Try a change

Before and after activation, run python -c "import sys; print(sys.executable)". What should change?

Check your reasoning

Look for a path ending in bin/python or Scripts/python.exe within the activated environment. Select the same interpreter in the editor.

Run a project with uv

A virtual environment gives a project its own Python environment and installed packages. A project-local .venv lives inside the project folder. An environment stored elsewhere can still be isolated. For a shared repository, use a project-local environment so each teammate can recreate it.

Install uv with Astral’s instructions, then open a fresh terminal in your practice folder. Create a new project and check which Python runs.

uv --version
uv init --bare --python 3.12 fde-uv-demo
cd fde-uv-demo

Inside fde-uv-demo, save this file as main.py.

print("Hello from the uv project!")

From the same folder, run the script and check which Python it used.

uv run python main.py
uv run python -c "import sys; print(sys.executable)"

The script prints Hello from the uv project!. The last command should show an executable inside fde-uv-demo/.venv. uv run can prepare the project’s environment and run the command without manual activation. The Python version here matches the lecture example.

To use this project in a notebook, add the kernel package and then select the project’s .venv in VS Code.

uv add --dev ipykernel
uv run python -c "import ipykernel; print(ipykernel.__version__)"

pyproject.toml declares the project dependencies. uv.lock records the resolved versions. Commit both files and let teammates run uv sync --locked from the project folder. Each teammate gets their own .venv.

1.7.5 pyproject.toml and formatting

Use pyproject.toml to record the supported Python version and formatting settings. This example reads TOML with tomllib, which is included in Python 3.11 and newer.

Run the code

import tomllib

text = """[project]
name = "transaction-tracker"
version = "0.1.0"
requires-python = ">=3.11"

[tool.ruff]
line-length = 88
"""
settings = tomllib.loads(text)
print(settings["project"]["name"])
print(settings["tool"]["ruff"]["line-length"])

Output

transaction-tracker
88

How it works

  1. [project] holds project metadata. [tool.ruff] holds Ruff settings.
  2. loads() returns nested dictionaries. Find line-length inside ruff inside tool.
  3. Configuration supplies settings when a tool is installed and run.
Common mistake

Use tested versions in a requirements file or use a lockfile. Verify installation in a clean environment. Formatters, linters and type checkers have different jobs.

With the environment active, use python -m pip install pytest==8.3.5 to install the pytest version used in this series. To set up formatting and linting, use python -m pip install ruff==0.11.13 mypy==1.15.0. These pins are examples. Run the tests if you update versions. python -m pip freeze > requirements-dev.txt records installed packages. Run it from an environment that contains only this project’s dependencies.

Try a change

A teammate copies pyproject.toml. Is pytest now available?

Check your reasoning

Create the environment and install the dependencies. Include the exact commands in the README.

Where to start debugging

If the import works in the terminal, compare interpreter paths with the editor. Test runtime validation for invalid API data. Reproduce dependency conflicts in a clean environment.

Practice 1: Typed Customer Lookup

Look up and return a customer name. Return None for a missing ID and let the caller choose the label.

Hint

Use str | None for the return type. Distinguish a missing record from an existing empty value.

See Solution

Use dict.get() and let the caller handle None explicitly.

Walk through the solution

get() returns None for a missing key. The caller checks for None and produces a readable label. The return annotation makes absence visible.

def find_customer(customers: dict[int, str], customer_id: int) -> str | None:
    return customers.get(customer_id)
customers = {42: 'Mynul'}
print('Check:', find_customer(customers, 42) == 'Mynul')
missing = find_customer(customers, 7)
label = 'unknown customer' if missing is None else missing
print('Check:', label == 'unknown customer')

Output

Check: True
Check: True

Test an empty map, a known ID and a missing ID. Explain what the type hint tells you and what you still need to validate.

Practice 2: Refactor Without Changing the Rule

Extract the review rule into a function. Amounts above 8,000 cents require review. Include tests for the boundary.

Hint

Keep the > comparison when the requirement says above.

See Solution

Let the function return the decision and the caller format it.

Walk through the solution

The function returns a decision. 8000 is normal and 8001 needs review. The checks catch changes to that boundary.

def review_status(amount_cents: int) -> str:
    if amount_cents < 0:
        raise ValueError('Amount cannot be negative')
    return 'review' if amount_cents > 8000 else 'normal'
print('Check:', review_status(0) == 'normal')
print('Check:', review_status(8000) == 'normal')
print('Check:', review_status(8001) == 'review')

Output

Check: True
Check: True
Check: True

Check your work

Run the script in a clean environment. Add setup instructions to the README and ask someone else to follow them.
