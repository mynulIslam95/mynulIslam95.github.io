1.7 Type Hints, Clean Code & Dependencies

তোমার script এখন teammate ব্যবহার করবে। কোন field required, function কী return করে আর কোন package লাগবে সেটা guess করতে হলে maintenance কঠিন হয়। এবার code-এর contract আর environment পরিষ্কার করি।

এই Lesson শেষে: Readable typed interfaces লিখতে, dependency environment isolate করতে আর ছোট project-এর setup document করতে পারবে।

1.7.1 Annotations and generic types

Teammate function call করতে গিয়ে expected input বুঝতে চায়। Type hints সেই contract communicate করে। এগুলো runtime input validation নয়। প্রথমে scalar annotation, পরে list-এর element type দেখি।

Code-টা run করি

def total_cents(amounts: list[int]) -> int:
    return sum(amounts)

print(total_cents([100, 250]))

Output

350

কীভাবে এই result হলো?

  1. amounts: list[int] বলে expected input integers-এর list।
  2. -> int বলে expected return integer।
  3. Function normal Python-এর মতো চলে; annotation নিজে validator নয়।
এখানে যেটা ভুল হতে পারে

Wrong type দিলে checker warn করতে পারে, কিন্তু Python annotation দেখে automatic reject করে না। Boundary validation এখনো প্রয়োজন।

Type hints complex business constraints যেমন positive amount, matching currency বা allowed tenant express করে validate করে না। Those rules explicit checks/tests-এ রাখতে হবে।

এবার তুমি বদলে দেখো

Function-এ str list পাঠালে annotation কি নিজেই block করবে?

Reasoning মিলিয়ে দেখো

না। Function body execute হবে এবং sum incompatible values পেলে runtime error হবে। Static checking আর runtime validation আলাদা layers।

1.7.2 Dataclasses and Optional

Ticket owner এখনো assign হয়নি। Empty string দিয়ে না ঢেকে None রাখি। str | None text অথবা absent বোঝায়। Default = None দিলে argument না দিয়েও object বানানো যায়।

Code-টা run করি

from dataclasses import dataclass

@dataclass
class Ticket:
    title: str
    owner: str | None = None

def owner_label(ticket: Ticket) -> str:
    if ticket.owner is None:
        return "unassigned"
    return ticket.owner

print(owner_label(Ticket("Refund")))
print(owner_label(Ticket("Delivery", "Mynul")))

Output

unassigned
Mynul

কীভাবে এই result হলো?

  1. প্রথম Ticket-এ owner omitted, default None হয়েছে।
  2. Explicit is None check-এ unassigned return হয়েছে।
  3. দ্বিতীয় ticket-এর real owner name অপরিবর্তিত return হয়েছে।
এখানে যেটা ভুল হতে পারে

Union type লিখলেই argument optional হয়ে যায় না। Default না দিলে caller-কে argument দিতেই হবে, যদিও allowed value None।

এবার তুমি বদলে দেখো

owner empty string হলে owner_label কী return করবে?

Reasoning মিলিয়ে দেখো

এই function empty string-ই return করবে, কারণ সেটা None নয়। Blank owner allowed কি না business validation-এ ঠিক করতে হবে।

1.7.3 Naming and refactoring

Code review-এ calculate(x) দেখলে x-এর unit বোঝা যাচ্ছে না। Refactor-এর উদ্দেশ্য শুধু কম line নয়, intention পরিষ্কার করা এবং expected behavior ধরে রাখা।

Code-টা run করি

def needs_review(amount_cents: int, threshold_cents: int = 8000) -> bool:
    return amount_cents > threshold_cents

print(needs_review(8000))
print(needs_review(8001))

Output

False
True

কীভাবে এই result হলো?

  1. Names বলছে amounts ও threshold একই unit cents।
  2. Default threshold reusable rule রাখছে।
  3. Exact boundary ও one-over-boundary output rule পরিষ্কার করছে।
এখানে যেটা ভুল হতে পারে

Refactor-এর সময় > থেকে >= করলে behavior বদলেছে। “Cleaner code” বলে business-rule change লুকাবে না। আগে baseline cases রাখো।

Calculation, input parsing, persistence আর formatting-এর boundaries useful। কিন্তু ছোট function-এর জন্য পাঁচটা abstraction layer বানিয়ে cognitive overhead বাড়ানো লাগবে না।

এবার তুমি বদলে দেখো

Threshold 10000 override করে 9000 input দিলে কী হবে?

Reasoning মিলিয়ে দেখো

needs_review(9000, threshold_cents=10000) False। Function name ও explicit argument দেখে rule change visible।

1.7.4 venv and pip

এক project-এর package অন্য project-এর সঙ্গে conflict করলে “আমার laptop-এ চলে” problem হয়। venv project-specific Python environment দেয়। প্রথমে কোন interpreter run হচ্ছে সেটা বুঝি।

Code-টা run করি

import sys
from pathlib import Path

print(Path(sys.executable).is_absolute())
print("Python", sys.version_info.major)

Output

True
Python 3

কীভাবে এই result হলো?

  1. sys.executable currently-running Python-এর location দেয়।
  2. এখানে True বলছে absolute interpreter path পাওয়া যাচ্ছে।
  3. sys.version_info.major দিয়ে major version দেখা যায়। Editor ও terminal একই environment ব্যবহার করছে কি না compare করতে real path print করো।
এখানে যেটা ভুল হতে পারে

pip install কোথায় যাচ্ছে সেটা না জেনে run করলে অন্য interpreter-এ package install হতে পারে। python -m pip ব্যবহার করলে সেই python-এর pip run হয়।

Terminal commands: python3 -m venv .venv, Linux/macOS-এ source .venv/bin/activate। Windows PowerShell-এ .venv\Scripts\Activate.ps1। Activate না করেও .venv-এর interpreter সরাসরি ব্যবহার করা যায়। Code .venv-এর ভিতরে রাখবে না, Git-এ environment commit করবে না।

এবার তুমি বদলে দেখো

venv activate করার আগে ও পরে python -c "import sys; print(sys.executable)" run করো। কী বদলানোর কথা?

Reasoning মিলিয়ে দেখো

Activated environment-এর bin/python বা Scripts/python.exe path দেখা উচিত। Editor-এও সেই interpreter select করবে।

1.7.5 pyproject.toml and formatting

Project-এর supported Python version আর formatting settings এক জায়গায় রাখবো। pyproject.toml হচ্ছে TOML configuration file। এটা Python code না। নিচের Python example TOML text read করে setting দেখাচ্ছে; tomllib Python 3.11+ standard library।

Code-টা run করি

import tomllib

text = """[project]
name = "transaction-tracker"
version = "0.1.0"
requires-python = ">=3.11"

[tool.ruff]
line-length = 88
"""
settings = tomllib.loads(text)
print(settings["project"]["name"])
print(settings["tool"]["ruff"]["line-length"])

Output

transaction-tracker
88

কীভাবে এই result হলো?

  1. [project] section metadata রাখে। [tool.ruff] শুধু Ruff-এর settings।
  2. loads nested dict তৈরি করেছে। tool-এর ভিতরে ruff, তার ভিতরে line-length।
  3. Configuration লেখা মানে tool install বা run করা না।
এখানে যেটা ভুল হতে পারে

pyproject.toml একা resolved dependency lock না। requirements file-এ tested versions বা chosen lock tool ব্যবহার করে clean environment-এ install verify করো। Formatter, linter, type checker আলাদা কাজ করে।

Activated venv-এ python -m pip install pytest==8.3.5 দিয়ে এই Lesson series-এর tested pytest version নিতে পারো। Code formatting/linting পরে python -m pip install ruff==0.11.13 mypy==1.15.0 দিয়ে tools setup করা যায়। এগুলো example pins; updated versions use করলে tests run করো। python -m pip freeze > requirements-dev.txt installed environment record করে; unrelated packages ছাড়া clean venv থেকে করো।

এবার তুমি বদলে দেখো

এক teammate শুধু pyproject.toml copy করেছে। pytest command automatically available হবে কি?

Reasoning মিলিয়ে দেখো

না। Environment create ও dependency install করতে হবে। README-তে exact setup commands লাগবে।

Debugging: কোথা থেকে শুরু করবে?

Terminal-এ import works কিন্তু editor-এ fail? Interpreter path compare করো। Hint আছে বলে invalid API payload safe মনে হচ্ছে? Runtime validation test করো। Package install হওয়ার পরে dependency conflict দেখলে clean environment-এ reproduce করো।

Practice 1: Typed Customer Lookup

Customer map থেকে name return করো। ID missing হলে None। Caller None handle করে label দেখাবে।

Hint

Return type str | None রাখো। Missing-কে existing empty value-এর সঙ্গে মিলাবে না।

See Solution

Dict.get দিয়ে missing represent করো, caller explicit None branch দেবে।

Solution-টা বুঝে নিই

get missing key-এ None দেয়। Caller explicit None branch-এ readable label বানিয়েছে। Typed return data absence visible করছে।

def find_customer(customers: dict[int, str], customer_id: int) -> str | None:
    return customers.get(customer_id)
customers = {42: 'Mynul'}
print('Check:', find_customer(customers, 42) == 'Mynul')
missing = find_customer(customers, 7)
label = 'unknown customer' if missing is None else missing
print('Check:', label == 'unknown customer')

Output

Check: True
Check: True

নিজের কাজ মিলিয়ে দেখো

Empty map, known ID ও missing ID test করো। Type hints validation নয়, এই difference explain করো।

Practice 2: Refactor Without Changing the Rule

৮০০০ cents-এর বেশি হলে review, অন্যথায় normal। Function-এ extract করো এবং boundary tests রাখো।

Hint

> আর >= এক না। Refactor-এর সময় business rule বদলাবে না।

See Solution

Pure classifier function রাখো; output formatting caller করবে।

Solution-টা বুঝে নিই

Function pure decision ফেরত দেয়। Boundary 8000 normal, 8001 review। Rule বদলালে checks expected mismatch দেখাবে।

def review_status(amount_cents: int) -> str:
    if amount_cents < 0:
        raise ValueError('Amount cannot be negative')
    return 'review' if amount_cents > 8000 else 'normal'
print('Check:', review_status(0) == 'normal')
print('Check:', review_status(8000) == 'normal')
print('Check:', review_status(8001) == 'review')

Output

Check: True
Check: True
Check: True

নিজের কাজ মিলিয়ে দেখো

Clean venv-এ script run করে setup steps README-তে লেখো। অন্য কাউকে command follow করতে দাও।
