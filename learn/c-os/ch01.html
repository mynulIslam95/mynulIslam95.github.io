C for OS · Chapter 1

A C file — main, compile, run

A program is a text file of rules. You compile it into a tool. You run the tool. The computer starts at main and follows the lines in order. No story. Trace every line.

Jump to practice

1. Three different things

Do not mix these three. Labs fail when you mix them.

  1. Source — a text file, usually lab.c. You can read it. The CPU does not run this file as-is.
  2. Compile — a program (gcc) reads the text and builds a machine tool. Example name: lab.
  3. Run — you start that tool. Then main runs.
The rule

Edit the .c file. Compile again. Then run. If you change the text and only run the old tool, you are running yesterday’s program.

2. The smallest program

#include <stdio.h>

int main(void) {
  return 0;
}

#include <stdio.h> means: copy the toolkit names for input and output (Chapter 10 will go deep). You need it as soon as you call printf. For this tiny file you could skip it, but labs always keep it. Habit: put it at the top.

int main(void) is the start function. int means main sends an integer back to the operating system. void in the brackets means main takes no arguments here.

The braces { } mark the body. Work lives between them.

return 0; sends 0 back to the OS: “this program ended without error.” A non-zero number usually means failure. Semicolon ends the statement. Without it, compile fails.

3. What actually runs, and in which order

The computer does not start at line 1 of the file. It starts at main. Then it runs the body from the opening brace downward, one statement after another, until return or the closing brace.

#include <stdio.h>

int main(void) {
  printf("A\n");
  printf("B\n");
  return 0;
}
Trace 
1. OS starts the tool.
2. Jump to main.
3. Print A (and a new line).
4. Print B (and a new line).
5. return 0 — main ends. OS takes 0.
Output:
A
B

If you put a second function in the file (Chapter 7), that function runs only when you call it. Defining it is not running it. For this chapter: everything you want to happen must sit inside main, in order.

4. Compile and run, by hand

gcc hello.c -o hello
./hello

gcc hello.c -o hello reads hello.c and writes a tool named hello. -o means “output name.”

./hello runs that tool in the current folder. The ./ means “here.” On Windows in some labs you type hello.exe. Same idea: run the tool, not the .c text.

If compile fails, there is no new tool (or the old one stays). Read the first error. Line numbers in the error point at the .c file, not at the running program.

Later labs add flags: gcc lab.c -o lab -lpthread -lrt. That is still this chapter plus Chapter 10. The extra words are libraries. The shape is the same: compile, then run.

5. Comments — for humans, not for the CPU

/* this block is ignored */
int main(void) {
  return 0;  // this rest of line is ignored
}

/* ... */ can span lines. // runs to the end of that line. Comments do not change what prints. They are how you will read your own lab at 1 a.m. In this course, See answer uses comments to teach. Your Submit answers may include comments; the checker ignores them.

6. Braces, statements, one main

  • Every ( needs ). Every { needs }.
  • One main per program. Two mains: the linker fights you.
  • The file name can be anything ending in .c. The function must still be named main. The OS looks for that name, not for the file name.
OS door

GPIO, scheduler, signals, Windows labs: they are still a .c file with main. You compile. You run. If the professor’s ZIP has gcc ... in a README, that line is this chapter. You will not get a different language for the OS exam.
