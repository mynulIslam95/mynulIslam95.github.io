Choice — if / else

Which branch runs. == vs =. This is the line if (r == 0) after fork. Trace the test, then only one body.

Jump to practice Ch3 print

1. A test, then a body

if (x == 0) {
  printf("zero\n");
} else {
  printf("not\n");
}
The rule

The test is in round brackets. If it is true (non-zero), the if body runs. Otherwise the else body runs, if you wrote one. Never both. After the whole if/else, the next line of main runs.

True in C: any non-zero number. if (3) is true. if (0) is false. Prefer a real comparison: x == 0, p != NULL, fd == -1.

2. == vs =

== asks: are these values the same? It does not write the box.

= writes. if (x = 0) sets x to 0, then the test is 0, which is false. You smashed the box and took the wrong branch. Write == for tests. Always.

Other tests: != not equal, < > <= >=.

Combine: && and, || or. if (r > 0 && fd != -1) — both must be true.

3. Braces

Use braces even for one line. OS labs nest ifs. Without braces, only the next statement belongs to the if. You will think a wait is in the parent and it will not be.

if (r == 0)
  printf("child\n");
  wait(NULL);    /* this is NOT inside the if. it always runs. */

4. else if chain — fork

pid_t r = fork();
if (r == 0) {
  /* child */
} else if (r > 0) {
  /* parent. r is child's pid */
} else {
  /* r == -1. fail. still only parent */
}

One process only ever takes one of these three. After a successful fork there are two processes: one has r==0, one has r>0. Each traces its own if. That is not “C ran both branches in one process.”

if (fork() == 0) is the same test without storing r. Then the parent cannot waitpid on that pid unless you stored it. Prefer a box: r = fork();

5. Error checks are ifs

if (fd == -1) { perror("shm_open"); return 1; }
if (p == MAP_FAILED) { perror("mmap"); return 1; }
if (p == NULL) { /* do not open */ }

These are Chapter 4 plus Chapter 2 boxes. The lab looks long because there are many ifs, not because C changed.

OS door

Child vs parent is an if on an int. Mutex code is not an if for “is it locked” in the beginner picture — you call lock (Chapter 7) and wait inside that call. Do not write if (mutex) instead of lock(&m).
