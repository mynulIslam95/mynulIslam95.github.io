C for OS · Chapter 9

Structs — several fields, one object

One name for a bundle. Then you put that bundle in shared memory: counters plus a lock. Without a struct you pass four pointers and lose the lock.

Jump to practice Ch8 pointers

1. Why a struct exists

A process in your head is not one int. It has a pid, a state, maybe a pointer to a page table. Shared memory for the exam is not one int. It is at least a counter and a mutex. A struct is one object with several named fields.

The rule

You still have one box. Inside it, labelled inner boxes (fields). You carry one address for the whole object. That is why mmap of sizeof(struct Block) is the exam pattern.

struct Point {
  int x;
  int y;
};

int main(void) {
  struct Point p;
  p.x = 2;     /* dot: the object is not a pointer */
  p.y = 3;
  return 0;
}

2. Dot vs arrow

If you have the object itself, use dot: p.x.

If you have a paper to the object, use arrow: sp->x. That is exactly (*sp).x. The arrow opens the box, then selects the field.

struct Point p;
struct Point *sp = &p;   /* paper to the same object */
p.x = 2;
sp->y = 3;               /* writes p.y */
/* now p.x is 2, p.y is 3. ONE object. */

OS code is almost all arrows, because you hold a pointer from mmap or from a function argument. Learn -> until it is boring.

3. Copy vs share

struct Point b = a; copies every field into a second object. Changing b.x does not change a.x.

struct Point *q = &a; copies the paper. One object. This is Chapter 8 inside a struct.

Threads must share. So they do not copy the struct by value into each thread’s private stack as “the” shared state. They each get a pointer to one struct.

4. Nested: a lock living next to the data

This is the exam picture. One shared block:

#include <pthread.h>

struct Block {
  pthread_mutex_t lock;  /* the lock is a FIELD */
  int count;             /* the data the lock protects */
  int done;
};

Why together? Because whoever maps the block sees both. If the mutex lived in process A only, process B cannot lock it. If count lived in a different mapping, you can lock the wrong thing.

Use:

struct Block *b;   /* paper from mmap, Chapter 8 */
pthread_mutex_lock(&b->lock);   /* paper to the FIELD inside the object */
b->count = b->count + 1;
pthread_mutex_unlock(&b->lock);
Trace the papers 
b            paper to the whole Block (shared bytes)
&b->lock     paper to the mutex field inside that Block
b->count     the int field, opened through the same object

Two threads: each has its own paper variable, both addresses
are the same mapping. One lock box. One count box.

Init once: pthread_mutex_init(&b->lock, NULL); before other threads or processes use it. Unlock is a function call (Chapter 7) on a pointer (Chapter 8) to a field (this chapter).

5. sizeof and mmap

sizeof(struct Block) is how many bytes the object needs. You pass that to ftruncate and mmap so the window is big enough for lock + counters. If you map only sizeof(int), the mutex does not fit. You will smash memory. Always size the mapping to the struct.

ftruncate(fd, sizeof(struct Block));
struct Block *b = mmap(NULL, sizeof(struct Block),
                       PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);

6. Passing a struct into a function

By value: the function gets a copy. Expensive, and changes do not come back (unless you return the copy).

By pointer: what goes in is the address. The callee opens the same object. This is how thread start functions and almost all OS helpers take a struct.

void bump(struct Block *b) {
  pthread_mutex_lock(&b->lock);
  b->count++;
  pthread_mutex_unlock(&b->lock);
}

Who waits: the caller waits for bump. Inside bump, the thread may also wait inside lock if another thread holds the mutex. That is a second wait, still “the caller of that function waits.”

7. Typedef (optional, you will see it)

typedef struct Block Block; lets you write Block *b instead of struct Block *b. Same object. Do not let the extra word scare you.

OS door

Shared memory in the exam is this object: lock + counters (and maybe a semaphore field). GPIO mmap is a different struct of registers. Same C: fields, pointer, sizeof.
