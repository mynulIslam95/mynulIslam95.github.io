Variables — int and char

One name, one box, one value. A new assignment replaces the old value. That is how a PID, a count, and a flag live in a lab file.

Jump to practice Ch1 file

1. A box with a name

A variable is a box in memory. It has:

  • a name you chose (x, count, pid)
  • a type (what kind of value fits)
  • a value (what is in the box now)
The rule

int x = 5; makes an int box named x and puts 5 in it. Later x = 9; does not make a second box. It replaces 5 with 9. After that, the old 5 is gone.

int x;      /* box exists. value is GARBAGE until you write one */
x = 5;      /* now 5 */
x = 9;      /* now 9. not 5, not 14 */

2. int — whole numbers

int holds a whole number (no fraction): 0, 1, -1, 42. Process ids, counts, file descriptors, return codes: almost all are int (or a typedef that is an int, like pid_t). For tracing, treat pid_t as int.

int x = 5; is declare and initialise. You may split: int x; then x = 5;.

Uninitialised: if you declare int x; and print x before any assignment, the value is garbage (whatever bits were there). Do not do that. Give a value first. Flags start at 0. Counts start at 0.

3. Assignment vs algebra

In maths, x = x + 1 is false. In C it is a command: read the box, add 1, write it back.

int n = 3;
n = n + 1;   /* read 3, write 4. n is now 4 */
n++;         /* same idea: add 1. n is 5 */

= is not “equals.” Equals as a test is == (Chapter 4). Mixing them is the most expensive one-character bug in this course.

4. char — one character, actually a small int

char c = 'A'; — single quotes. One character. Double quotes "A" are a string (a small array, Chapter 6). Do not mix them yet.

A char is stored as a small integer (the code for that character). You may do c + 1 in traces. You rarely need that for OS labs. You need char for letters in a name like /myshm (Chapter 6) and for tiny flags some people store as char. Prefer int for counts and pids.

5. Names you will see in labs

  • pid — process id, an int (or pid_t)
  • fd — file descriptor, an int, often from shm_open or open
  • count — how many times something happened
  • flag / got / done — 0 or 1. Off or on.

These are not new types. They are ints with a job. A flag that is 1 is still an int 1. Later volatile int got is still this box, with one extra word (Chapter 8).

6. Two boxes, two names

int a = 1;
int b = a;   /* copy the VALUE 1 into a new box b */
b = 9;       /* a is still 1 */

Copying the value is not sharing the box. Sharing the box needs a pointer (Chapter 8). For this chapter: two names, two boxes, unless you later point both papers at one box.

OS door

fork returns into an int box: pid_t r = fork(); That is this chapter. The meaning of 0 / pid / -1 is Chapter 7. The box is an int. Put a value in. Replace it. Read it in an if (Chapter 4).
