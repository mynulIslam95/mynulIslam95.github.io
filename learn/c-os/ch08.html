C for OS · Chapter 8

Pointers — & and *

Paper vs box. Two papers, one box. This is the hardest C chapter and the hinge for mutex, mmap, and GPIO. If you only memorise stars, you will fail the lab files. Trace the address.

Jump to practice Ch7 functions

1. Two different things

A box is a variable in memory. It has a name, a type, a value, and an address (where it lives).

A paper is a pointer. The value stored on the paper is not “the money.” It is the address of a box.

The rule — never mix these
  • int x = 5; — box named x, value 5.
  • &x — the address of that box (you write the address on a paper).
  • int *p; — paper p. It is meant to hold the address of an int box.
  • p = &x; — write x’s address on the paper.
  • *p — open the box whose address is on the paper. That is 5. If you assign *p = 9, the box x becomes 9.

* in the declaration int *p means “paper for an int.” * in an expression *p means “open the box.” Same character, two jobs. Say the job out loud.

2. One picture you will reuse in every OS lab

Box x at address 0x100:   [ 5 ]

Paper p:                  [ 0x100 ]   p == &x
*p means: go to 0x100     so *p is 5, and x is 5

Paper q:                  [ 0x100 ]   q = p;  (copy the paper, not the box)
Now two papers, ONE box.
*q = 9;                   box x is 9. *p is also 9.

Copying a pointer copies the address. It does not create a second int. This is “two papers, one box.” Threads, mutex, shared memory all sit on this sentence.

3. Full program, line by line

#include <stdio.h>

int main(void) {
  int x = 5;
  int *p;
  p = &x;
  printf("%d\n", *p);   /* 5 */
  *p = 9;
  printf("%d\n", x);    /* 9 — same box */
  return 0;
}
Trace 
1. Box x holds 5.
2. Paper p exists. Address on it is garbage until we write one.
3. p = &x  writes x's address on the paper.
4. *p reads the box. Prints 5.
5. *p = 9 writes 9 into that box.
6. x is 9. There was never a second int.

4. Why Chapter 7 was not enough

Pass by value copies the number. A function cannot change the caller’s box if it only receives the number.

void bump(int n) { n = n + 1; }      /* copy. caller unchanged */

void bump_box(int *p) { *p = *p + 1; }  /* paper. opens the caller's box */

int main(void) {
  int x = 4;
  bump(x);        /* x still 4 */
  bump_box(&x);   /* pass THE ADDRESS. x becomes 5 */
  return 0;
}

Read bump_box(&x) as: “here is the paper for x. Open that box.” What goes in is an address. What comes back is void. Who waits: main waits until bump_box returns. After return, x is changed because both used the same box.

This is exactly why mutex functions take a pointer. If they took the mutex by value, they would lock a copy. The other thread would lock a different copy. The lock would be a lie.

5. NULL — a paper that must not be opened

NULL is a special address meaning “nowhere.” You may store it on a paper: p = NULL;. You must not do *p. Opening nowhere crashes (undefined behaviour; on Linux you usually see a segmentation fault).

Many OS functions return a pointer. Failure is NULL (or MAP_FAILED for mmap, which is also “this is not a usable paper”). Always test the paper before you open it.

int *p = NULL;
if (p != NULL) {
  *p = 1;    /* skipped. safe */
}

6. void * — a paper without a type yet

void * means “a paper that points at some bytes, type not specified.” mmap returns void * because the kernel does not know if you will treat the bytes as ints, a struct, or GPIO registers. You assign it to the type you need:

void *raw = mmap(...);
int *nums = raw;           /* treat bytes as ints */
/* or */
struct Block *b = raw;     /* Chapter 9 */

You do not write *raw as if it were an int. First you choose the type of paper.

7. Pointer vs array (only what OS C needs)

An array is many boxes in a row. The name a in int a[4] can decay to a paper for the first box. &a[0] is that address. You need this for a name string "/myshm" and for small buffers. You do not need pointer arithmetic contests.

char name[] = "/myshm";   /* boxes for each letter, plus '\0' */
/* shm_open wants a paper to the first character: name or &name[0] */

8. Function pointer — paper that points at a job

Chapter 7: a signal handler is a function you do not call yourself. signal(SIGUSR1, handler) needs the address of the function. That is a paper whose box is code, not an int.

You write the name handler without calling it (no ()). With () you would run it now. Without () you pass the paper.

9. volatile — the box may change behind your back

A signal handler, or hardware, can change a box while main is looking at it. volatile int flag tells the compiler: “every time you read this, really read the box. Do not assume it is still 0.” One line. Not a new chapter. You will put volatile on the flag the handler sets.

OS door — same paper/box rule

Mutex, mmap, GPIO are not new C. They are “two papers, one box” in three places.

10. Mutex — lock the box, not a copy

pthread_mutex_t m; is a box (the lock object). pthread_mutex_lock(&m) takes a paper to that box.

pthread_mutex_t m;
pthread_mutex_init(&m, NULL);
pthread_mutex_lock(&m);     /* paper: the SAME mutex both threads must use */
/* critical: touch the shared int here */
pthread_mutex_unlock(&m);

If two threads each had their own m, two papers would point at two boxes. Both would “lock” and both would still race. Shared mutex = one mutex box, two threads holding papers to it.

A counting semaphore is the same idea: the functions take a pointer to one semaphore object both sides must see.

11. mmap — a paper to a window of bytes

mmap is a function. What comes back is a pointer (or MAP_FAILED).

With MAP_SHARED, that paper points at bytes the kernel also maps for another process (or for a file, or for hardware). Two processes, two papers, one shared box (or one shared struct). If process A writes *p = 7, process B’s paper sees 7.

That is shared memory in C clothing. You will put a struct there in Chapter 9 (counters + lock).

int fd = shm_open("/myshm", O_RDWR, 0600);
ftruncate(fd, sizeof(int));
int *p = mmap(NULL, sizeof(int), PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
if (p == MAP_FAILED) { /* bad paper. do not open */ }
*p = 1;   /* write into the SHARED box */

Who waits: mmap returns when the mapping is set up. It does not wait for the other process. The other process must map the same object and get its own paper to the same bytes.

12. GPIO — a paper to hardware registers

Lab 1 is not a new kind of star. You open /dev/mem (or the Pi’s gpiochip path in the lab story), then mmap a window onto device registers. The return value is a paper. You write to *reg or to a field, and a pin changes. The box is not a normal RAM variable you declared. It is hardware. Still: paper vs box. Do not copy the register by value and expect the pin to move. Write through the pointer.

volatile appears again: the register can change without your C code writing it. Read the box every time.

13. Mistakes that fail the exam file

  • Using p when you meant *p (printing the address, or passing a paper where an int is needed).
  • Using *p when p is NULL.
  • Passing m instead of &m to lock.
  • Thinking two pointer variables means two mutexes or two shared ints.
  • Forgetting that fork copies the papers. After fork, parent and child have copies of the pointer value. If the mapping is MAP_SHARED, those copies still point at the same physical box. If it is private memory, each has its own box. That sentence is the process/thread/shm hinge.
Boss test

For every pointer in a lab: name the paper, name the box, say how many boxes exist, say who else holds a paper to that box. If you cannot, do the practice. Do not skip to OS stories.
