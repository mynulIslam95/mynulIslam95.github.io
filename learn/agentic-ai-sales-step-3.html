Before you start

Request Errors handle করতে পারবে আর Step 1-এর Expected Decisions থাকবে। এবার Text Report-এর বদলে একটি Data Contract তৈরি করবো। Contract-এর Fields UI, Database আর Evaluation-এ একই অর্থ বহন করবে।

Understand the contract

  • Pydantic Model Data Types ও Constraints Validate করে। Schema ঠিক হলেও Claim সত্য কি না আলাদা Evidence Check লাগে।
  • Literal দিয়ে Allowed Decisions সীমিত করবো। Unknown Case-এর জন্য insufficient_evidence রাখবো, কারণ সব Company-কে Fit বা Not Fit-এ force করা ঠিক হবে না।
  • Nested Models-এ Evidence Record রাখলে source_id, quote ও reason আলাদা করা যায়। প্রথম Lab সরল রাখতে Evidence IDs ব্যবহার করছে।
  • extra="forbid" Unexpected Field reject করে। strict=True silently Wrong Type Convert হওয়া কমায়। Whitespace-only String-এর জন্য strip বা Validator আলাদাভাবে লাগবে।
  • Structured Output Support থাকলে Provider-কে Schema পাঠাবে। তার পরেও Refusal, Output Limit ও Parsing Error-এর handling রাখবে।

Build tasks

  1. app/schemas.py-তে Report, EvidenceReference আর InputProfile Models লেখো। Field Meaning docs/data-contract.md-এ রাখো।
  2. Valid, Missing Field, Wrong Decision, Extra Field আর Empty Reasons-এর JSON Fixtures বানাও।
  3. Model Adapter-এ Supported Schema Output Configure করো। SDK Integration থেকে Schema Validation আলাদা Function-এ রাখো।
  4. Validation Failure হলে Raw Output User-কে Final Report হিসেবে দেখাবে না। One Controlled Repair Attempt দরকার হলে total Budget-এর মধ্যে রাখো।
  5. Report-এর সব evidence_id Retrieved Source Set-এ আছে কি না Check করো। List-এ ID থাকা মানেই Claim Supported হয়েছে, এমন অনুমান করবে না।
  6. UI-তে Decision, Reasons ও Missing Information আলাদা দেখাও। JSON Download বা CLI JSON Output যোগ করো।

Worked local lab

lab_3.py

from typing import Literal
from pydantic import BaseModel, ConfigDict, Field, ValidationError, model_validator

class Report(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)
    company: str = Field(min_length=1)
    decision: Literal["fit", "not_fit", "insufficient_evidence"]
    reasons: list[str] = Field(min_length=1)
    evidence_ids: list[str]
    missing_information: list[str]

    @model_validator(mode="after")
    def require_evidence(self):
        if self.decision != "insufficient_evidence" and not self.evidence_ids:
            raise ValueError("A supported decision needs evidence references")
        return self

if __name__ == "__main__":
    raw = '{"company":"Example Tools","decision":"fit",' \
          '"reasons":["Explicit cloud migration project"],' \
          '"evidence_ids":["doc-1"],"missing_information":[]}'
    report = Report.model_validate_json(raw)
    assert report.decision == "fit"
    print(report.model_dump_json())
    try:
        Report.model_validate({"company": "Example Tools", "decision": "maybe"})
    except ValidationError:
        print("Invalid report rejected")
    else:
        raise AssertionError("Invalid report was accepted")

Dependencies-এ Pydantic লাগবে। python lab_3.py চালালে Valid Report JSON আর Invalid report rejected দেখা যাবে। Report-এর Structure যাচাই হলো, Evidence Text-এর Quality Step 4-এ পরীক্ষা করবো।

Practice & debugging

  • Whitespace-only Company Name reject করার Validator যোগ করো।
  • Fit Decision-এ Fake evidence_id দিলে Schema Pass করতে পারে। Known Source IDs দিয়ে Semantic Validation Function লেখো।
  • Unsupported Claim-সহ Valid JSON বানাও। Structural Pass আর Factual Failure আলাদা Test হিসেবে রাখো।
  • pytest.parametrize দিয়ে ৫টা Invalid Fixture পরীক্ষা করো। pytest.raises(ValidationError) ব্যবহার করো।
Solution approach

Model Field Validation-এর পরে Evidence Resolver চালাও। Unknown ID হলে Reject করো। প্রতিটি Claim-এর Quote Source Text-এ আছে কি না Check করে Human-Labeled Cases দিয়ে Meaning Review করো। Generated Text-কে নিজেই Ground Truth বানাবে না।
