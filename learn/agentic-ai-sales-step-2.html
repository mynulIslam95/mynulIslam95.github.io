Before you start

Step 1-এর CLI, Criteria আর Profile Fixtures থাকবে। Function Arguments, Return Values আর Exceptions বোঝা শুরু করবে। এবার একটি Request-এর Lifetime অনুসরণ করে Failure Handling যোগ করবো।

Request lifecycle

  1. Input Receive — Blank Text reject করো, Input Size Limit নির্ধারণ করো আর একটি Request ID দাও।
  2. Request Build — Model Name, Instructions আর Profile আলাদা fields-এ পাঠাও। Model Parameters Support Provider Documentation দিয়ে মিলিয়ে নাও।
  3. Await Response — Connection Timeout ও Response Timeout-এর Budget রাখো। Concurrent Requests-এর আগে Sequential Flow বুঝে নাও।
  4. Handle Result — Complete, Incomplete, Refused ও Failed Outcome আলাদা করো। Stream শুরু হওয়া আর Response Successfully Complete হওয়া আলাদা Events।
  5. Record — Request ID, Duration, Attempt Count আর Error Category log করো। Sensitive Profile Text logging-এর প্রয়োজন ও retention ঠিক করো।

Concepts you will use

  • HTTP Status Code Transport Outcome জানায়। HTTP Success পেলেও Output Business Criteria পূরণ করছে কি না Step 3-এ Validate করতে হবে।
  • JSON দিয়ে Strings, Numbers, Lists, Objects, true/false ও null পাঠানো যায়। Python-এ json.loads আর json.dumps দিয়ে convert করবো।
  • Timeout বা Rate Limit কখন retry করা যায় সেটার Policy লিখবো। Invalid API Key বা Invalid Input নিজের থেকে বারবার retry করবো না।
  • SDK Retry আর Application Retry একসাথে থাকলে Attempts বেড়ে যেতে পারে। একটি Layer-এ Policy রাখো আর Total Deadline নির্ধারণ করো।
  • Async Work-এ Blocking sleep ব্যবহার না করে asynchronous waiting করো। Cancellation Propagate করো যাতে User চলে গেলে Unnecessary Work চলতে না থাকে।

Worked local lab

lab_2.py

import json
from collections.abc import Callable

class TemporaryFailure(Exception):
    pass

def bounded_call(operation: Callable[[], str], attempts: int = 3) -> dict:
    if attempts < 1:
        raise ValueError("attempts must be positive")
    for attempt in range(1, attempts + 1):
        try:
            return {"text": operation(), "attempts": attempt}
        except TemporaryFailure:
            if attempt == attempts:
                raise
    raise AssertionError("Unreachable")

if __name__ == "__main__":
    calls = {"count": 0}
    def fake_model() -> str:
        calls["count"] += 1
        if calls["count"] < 3:
            raise TemporaryFailure("Synthetic timeout")
        return "Research complete"

    result = bounded_call(fake_model)
    assert result["attempts"] == 3
    print(json.dumps(result))

python lab_2.py চালালে attempts হবে 3। এখানে Waiting বাদ দেওয়া হয়েছে যাতে Deterministic Lab দ্রুত চলে। Actual Provider Adapter-এর Retry Delay ও Deadline আলাদা Implementation Task।

Debugging exercises

  • Operation সবসময় TemporaryFailure দিলে Exactly কয়বার Call হবে? Counter দিয়ে Verify করো।
  • একটি ValueError তুললে Retry হবে কি? কোন Exception ধরা হয়েছে সেটা দেখো।
  • Stream-এর তিনটা Chunk পাওয়ার পর Connection বন্ধ হলো। Saved Report-কে Complete হিসেবে দেখালে Bug হবে কেন?
  • Retry করার আগে Complete Stream User-কে আবার পাঠালে Duplicate Text হতে পারে। Restart বা Resume Policy লিখো।
Expected diagnosis

Only TemporaryFailure retry হয়। attempts=0 immediate Validation Error। Exhausted Retry Failure Caller-এর কাছে যায়। Partial Stream-এ failed/incomplete Status রাখো। Resending Entire Stream হলে UI Buffer Reset বা নতুন Attempt Identity প্রয়োজন।

Latency budget & reliability boundaries

এই Step-এর System Design Review-এ নিচের Decisions লিখবো আর Evidence দিয়ে ব্যাখ্যা করবো।

  1. একটি Request-এর Queue, Retrieval, Model আর Validation Time আলাদা Budget করো। Overall Deadline থেকে প্রতিটি Stage-এর Budget বরাদ্দ করো।
  2. Retry Budget সব Layer মিলিয়ে গুনবে। 3 App Attempts × 3 SDK Attempts হলে 9 Requests হতে পারে। Configuration দিয়ে এই Multiplication ঠেকাও।
  3. Streaming-এর Contract define করো — Run ID, Event Sequence, Partial Output, Final Status আর Disconnect Behaviour। Backpressure ও Max Concurrent Streams-এর Policy লিখো।
  4. ADR-002-এ Sync vs Async ব্যাখ্যা করো। Slow I/O-তে Async সুবিধা দিতে পারে, কিন্তু Provider Quota আর GPU Capacity নিজে বাড়ায় না।
