START FROM ZERO

Set up a real SQL practice database

SQL is a language used to query relational databases. This chapter uses SQLite and Python's built-in sqlite3 module so that a beginner can start without installing a database server. The same core SQL concepts transfer to PostgreSQL and other relational databases, although some functions and syntax differ.

  1. Install Python 3 and VS Code if they are not installed. Open VS Code and choose File → Open Folder. Create and open sql-foundations.
  2. Choose Terminal → New Terminal. Verify Python with python --version or python3 --version.
  3. Create setup.sql and paste the dataset below. This dataset intentionally includes missing references and missing values to practice data-quality checks.
  4. Create run_sql.py with the runner below. Run python run_sql.py setup.sql (or use python3 where necessary).
  5. Create query.sql. Put a single SELECT statement inside and run python run_sql.py query.sql. Change the query, save and rerun.

run_sql.py: a small query runner

from pathlib import Path
import sqlite3
import sys

if len(sys.argv) != 2:
    raise SystemExit('Usage: python run_sql.py file.sql')
sql = Path(sys.argv[1]).read_text(encoding='utf-8')
with sqlite3.connect('practice.db') as conn:
    if Path(sys.argv[1]).name == 'setup.sql':
        conn.executescript(sql)
        print('Database setup complete.')
    else:
        cursor = conn.execute(sql)
        if cursor.description:
            print(' | '.join(col[0] for col in cursor.description))
            for row in cursor.fetchall():
                print(' | '.join('NULL' if x is None else str(x) for x in row))

Important: Run setup.sql only once for the initial dataset. Running it again without deleting practice.db raises an error because the tables already exist. To reset the exercise, delete practice.db and run setup.sql again. Use one SELECT statement per query.sql file with this beginner runner.

First successful query

SELECT COUNT(*) AS customer_count FROM customers;

Expected output: customer_count followed by 5. If you see no such table, setup.sql was not executed against the same practice.db file. If you see no such file, check the terminal's current folder and the filename.

LESSON 1

Relational tables and first SELECT

Understand

A table has rows (records) and columns (fields). A primary key identifies a row. A customer_id in orders is intended to refer to customers.customer_id. The practice dataset deliberately contains unmatched references, so no foreign-key constraint is enforced.

Run this query

SELECT customer_id, name, city
FROM customers;

Expected rows

1 | Amina | Hamburg
2 | Ben | Berlin
3 | Chloe | NULL
4 | David | Hamburg
5 | Eva | Munich

Read the query, line by line

  1. SELECT chooses columns; FROM chooses the table.
  2. The semicolon ends a SQL statement. A string value is enclosed in single quotes.
  3. A primary key identifies one row. A reference column may repeat because a customer can have multiple orders.
Practice, debug and explain

Independent task

Select name and city for every customer. Then select only the name of customer 2.

  3. Inspect raw rows before adding filters, grouping or joins.
  4. Predict the result first, then run the query and compare.
Reveal one possible solution

LESSON 2

Filtering with WHERE

Understand

WHERE filters individual rows before they are returned. Conditions include =, !=, >, <, >=, <=, AND, OR and IN. Strings need single quotes.

Run this query

SELECT order_id, amount
FROM orders
WHERE amount >= 100;

Expected rows

101 | 120
103 | 200
105 | 100

Read the query, line by line

  1. WHERE amount >= 100 excludes 80, 50, 75 and 40.
  2. NULL is unknown, so NULL >= 100 is not true.
  3. AND requires both conditions; OR requires at least one.
Practice, debug and explain

LESSON 3

Sorting with ORDER BY and LIMIT

Understand

ORDER BY controls the result order. ASC means ascending, DESC descending. LIMIT returns at most a chosen number of rows. Without ORDER BY, top-N results are not reliably defined.

Run this query

SELECT order_id, amount
FROM orders
WHERE amount IS NOT NULL
ORDER BY amount DESC, order_id ASC
LIMIT 3;

Expected rows

103 | 200
101 | 120
105 | 100

Read the query, line by line

  1. WHERE removes NULL amounts first.
  2. ORDER BY amount DESC puts the largest first.
  3. order_id ASC breaks ties consistently. LIMIT 3 keeps the first three sorted rows.

LESSON 4

COUNT, SUM and AVG

Understand

Aggregate functions summarize rows. COUNT(*) counts rows. COUNT(column) counts non-NULL values in that column. SUM and AVG ignore NULL values. A missing numeric value is not automatically zero.

Run this query

SELECT COUNT(*) AS order_rows,
       COUNT(amount) AS known_amounts,
       SUM(amount) AS revenue,
       ROUND(AVG(amount),2) AS average_amount
FROM orders;

Expected rows

8 | 7 | 665 | 95.0

Read the query, line by line

  1. Eight rows exist, but one amount is NULL.
  2. SUM includes seven known amounts: 120+80+200+50+100+75+40 = 665.
  3. AVG divides 665 by 7, not by 8. ROUND controls displayed decimal precision.
Practice, debug and explain

Independent task

Debugging checklist

  1. Confirm the table and column names match setup.sql exactly.
  2. Check parentheses, quotes, commas and the order of SQL clauses.
  3. Inspect raw rows before adding filters, grouping or joins.
  4. Predict the result first, then run the query and compare.
Reveal one possible solution

FROM orders;

Explain without notes

LESSON 5

GROUP BY and HAVING

Understand

GROUP BY forms one summary row for each distinct group. WHERE filters source rows before grouping. HAVING filters groups after aggregates are calculated.

Run this query

SELECT customer_id, COUNT(*) AS orders_count,
       SUM(amount) AS revenue
FROM orders
GROUP BY customer_id
HAVING SUM(amount) >= 100
ORDER BY revenue DESC;

Expected rows

2 | 2 | 300
1 | 3 | 200

Read the query, line by line

  1. Grouping creates one row per customer_id, including a separate NULL group.
  2. COUNT(*) includes the order with a NULL amount.
  3. HAVING SUM(amount) >= 100 removes groups below the threshold. The result is sorted by revenue descending, so customer 2 appears before customer 1.
Practice, debug and explain

LESSON 6

INNER JOIN and LEFT JOIN

Understand

JOIN combines tables using a matching condition. INNER JOIN keeps matched pairs. LEFT JOIN keeps every row from the left table and fills missing right-side columns with NULL. A join can multiply rows when one customer has several orders.

Run this query

SELECT c.name, o.order_id, o.amount
FROM customers AS c
INNER JOIN orders AS o
  ON c.customer_id = o.customer_id
ORDER BY o.order_id;

Expected rows

Amina | 101 | 120
Amina | 102 | 80
Ben | 103 | 200
Chloe | 104 | 50
Ben | 105 | 100
Amina | 108 | NULL

Read the query, line by line

  1. The ON condition matches customer identifiers.
  2. Order 106 refers to customer 99, who does not exist; order 107 has NULL customer_id. Neither matches.
  3. INNER JOIN returns six rows. Customers with no orders do not appear.
Practice, debug and explain

Independent task

LESSON 7

NULL, IS NULL and COALESCE

Understand

NULL means missing or unknown. It is not the same as zero or an empty string. Use IS NULL or IS NOT NULL, not = NULL. COALESCE chooses the first non-NULL value. Use it only when a replacement has a justified meaning.

Run this query

SELECT order_id,
       amount,
       COALESCE(amount,0) AS amount_for_display
FROM orders
WHERE amount IS NULL;

Expected rows

108 | NULL | 0

Read the query, line by line

  1. WHERE amount IS NULL identifies the missing value.
  2. COALESCE(amount,0) displays 0 when amount is NULL.
  3. The original amount remains NULL. Treating unknown revenue as zero may be misleading in actual reports.

LESSON 8

Basic subqueries and business questions

Understand

A subquery is a SELECT nested inside another query. It can produce a value, a set of values or a derived table. Use it when a question naturally has two stages.

Run this query

SELECT name
FROM customers
WHERE customer_id IN (
  SELECT customer_id
  FROM orders
  WHERE amount >= 100
)
ORDER BY name;

Expected rows

Amina
Ben

Read the query, line by line

  1. The inner query finds customer IDs associated with orders of at least 100.
  2. The outer query finds the names of those customers.
  3. IN handles a set of values. NULL values do not produce a successful equality match.
Practice, debug and explain

Independent task

  3. Inspect raw rows before adding filters, grouping or joins.
  4. Predict the result first, then run the query and compare.

Step 1: Create the database

Step 4: Find monthly revenue

Interview questions with detailed answers

1. WHERE versus HAVING

WHERE filters individual input rows before grouping. HAVING filters grouped results after aggregate calculations. For example WHERE amount > 0 removes individual nonpositive rows, while HAVING SUM(amount) > 100 selects groups whose total exceeds 100.

2. INNER JOIN versus LEFT JOIN

INNER JOIN keeps rows for which the join condition matches. LEFT JOIN preserves all rows from the left table and fills missing right-side values with NULL. Choose the left table according to the business question: customers on the left for customers without orders, orders on the left for missing customer references.

3. COUNT(*) versus COUNT(column)

COUNT(*) counts all rows in a group. COUNT(column) counts only rows where that column is not NULL. In the practice orders table, COUNT(*) is 8 and COUNT(amount) is 7. Zero values are counted by both.

4. Why can a JOIN duplicate rows?

If a customer has multiple orders, joining that customer to orders produces one output row per matching order. If both join keys have duplicates, row multiplication can be larger. Check key uniqueness and compare row counts before and after joins.

5. Why does LEFT JOIN produce NULL?

When the left-side row has no matching right-side row, SQL preserves the left-side record and supplies NULL for the right-side columns. A NULL from an unmatched join is not necessarily a stored NULL in the right table.

6. What is the risk of COALESCE(amount,0)?

It can make missing revenue look like a known zero. COALESCE is useful for display or explicitly defined calculations, but it should not conceal missing business data without agreement on the metric.
