status-service-delivery

View repository

Problem

Northfield needs a tiny internal status service that can be released the same way every time, watched with metrics, broken on purpose, recovered, rolled back, and run on a local Kubernetes cluster.

What is in the repo

  • Python HTTP app: /health, /ready, /metrics. Non-root Docker image.
  • Compose: app, Prometheus, Grafana with a Northfield dashboard.
  • Unittest for 200 health, metrics text, and 503 when fail mode is on.
  • GitHub Actions: tests, image build, compose health. Image build is not a production deploy.
  • scripts/break.sh, recover.sh, rollback.sh.
  • Kubernetes Deployment, Service, ConfigMap, live and ready probes.

How to check it

python -m unittest tests/test_health.py then docker compose up --build and curl /health. Run break then recover. Apply k8s/status.yaml on kind or minikube and wait for rollout. If CI is red, do not call the pipeline green.
